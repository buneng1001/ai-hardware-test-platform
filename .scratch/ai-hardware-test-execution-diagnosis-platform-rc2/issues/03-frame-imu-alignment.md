# 03 — 实现独立时间对齐与逐帧视频—IMU 映射

**What to build:** 让测试工程师在不损坏原始时间证据的前提下，复核每一路视频帧与对齐后 IMU 样本之间的实际时间关系。

**Blocked by:** 02 — 升级合成数据与六轴 IMU 契约

**Status:** resolved
**Version:** v0.1.0-rc.2

- [x] 对齐时间作为独立派生结果保存，不覆盖视频或 IMU 的原始设备时间和相对时间。
- [x] 保留参考时钟、对齐方法、参数、对齐前指标和对齐后残差。
- [x] 对每一路视频的每一帧，从完成时钟对齐的 IMU 序列中选择时间差最小的样本。
- [x] 独立映射产物记录视频通道、帧号、双方原始/相对/对齐时间、IMU 样本序号、真实时间差、容差和匹配状态。
- [x] 运行详情、报告和证据包可引用映射产物，并覆盖不同采样率、无匹配和边界情况的公开 API 测试。

## Answer

- 新增独立 `frame-imu-alignment.csv` 派生产物和公开下载接口；每路视频逐帧选择对齐后最近邻 IMU 样本，记录双方原始设备时间、相对时间、对齐时间、样本序号、实际时间差、容差和匹配状态。
- 对齐结果新增映射摘要；报告和证据 ZIP 通过 artifact 清单引用映射文件，运行详情提供下载入口。原始视频和 IMU 文件不被覆盖；人工复核后会重算映射及其摘要。
- 视频 raw 时间由每路视频 artifact 的起始原始设备时间加容器 PTS 派生；合成视频保存该起始时间元数据。
- 验证证据：逐帧映射公开 API 测试 `2 passed`；相关对齐/报告回归 `14 passed`；后端完整测试 `109 passed`；前端完整测试 `26 passed`；前端 typecheck、Prettier、后端 Ruff check 和 `git diff --check` 通过。
- 前端完整测试首次在受限沙箱中因 Windows `spawn EPERM` 失败，获提升权限重跑后通过；后端 pytest 仅有缓存目录权限警告，不影响测试结果。
