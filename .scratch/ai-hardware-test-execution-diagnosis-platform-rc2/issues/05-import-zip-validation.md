# 05 — 实现实际测试 ZIP 导入与安全校验

**What to build:** 让测试工程师在独立的“根据导入生成”页面上传一个实际测试 ZIP，经分层安全和兼容性校验后创建尚未执行的导入型采集任务。

**Blocked by:** 01 — 重做页面导航与采集任务生命周期管理；02 — 升级合成数据与六轴 IMU 契约

**Status:** resolved
**Version:** v0.1.0-rc.2

- [x] 一次只接受一个 ZIP；页面提供导入、校验、转为标准格式和加入任务列表四个按钮，并按状态启用。
- [x] ZIP 必须包含 manifest、至少一路 1～4 路 H.264 MP4/MKV 视频和一个最低 100Hz 的六轴 IMU 文件。
- [x] manifest 声明通道、帧率、分辨率、码率、时间来源和每路视频的起始原始设备时间。
- [x] 校验区分安全/结构校验与平台兼容性校验，状态为通过、不通过或非标准但可转换；错误禁止入库，警告持续可见。
- [x] 实现哈希去重、同名异哈希区分、权限确认、Git 忽略隔离区、原子入库和临时隔离区手工移除。
- [x] 执行 2GiB ZIP、10GiB 解压、100 文件、5GiB 单文件、100:1 压缩比、路径穿越、加密压缩和 ZIP 炸弹边界检查。
- [x] 缺少可选状态/日志属于警告；实际数据不得伪造 fault_truth.json；转换入口首版只显示开发中提示。
- [x] 公开 API 和前端测试覆盖正常、损坏、恶意、重复、边界和重复请求场景。

## Answer

- 新增 `/api/imports` 上传、校验、转换占位和加入任务列表 API；上传流式写入 `data/imports/staging`，使用 SHA-256 去重。
- 校验 manifest、1～4 路 MP4/MKV、H.264 声明、视频参数、六轴 IMU、100Hz 下限、可选证据警告、路径穿越、加密条目、文件数、大小和压缩比边界。
- 通过后将原始 ZIP 与解压目录原子移动到正式哈希目录，并创建 `imported_actual_data` 草稿任务；重复导入返回已有记录关联信息。
- 前端根据导入页面展示上传/校验/转换/加入按钮、权限确认、进行中状态、错误和警告；转换入口仅提示“开发中”。

验证证据：后端 `backend/tests/test_import_zip_validation_api.py` 与全量测试 `115 passed`；前端 App 测试 `11 passed`、全量 Vitest `28 passed`；`pnpm typecheck`、`pnpm format:check`、本次文件 Ruff 检查通过。全量后端仅有既存 `.pytest_cache` 权限警告。
