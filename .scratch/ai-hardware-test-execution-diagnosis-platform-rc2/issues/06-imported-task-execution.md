# 06 — 让导入型任务进入统一运行与分析链路

**What to build:** 让测试工程师在导入任务入列表后手工配置并启动运行，获得适用的确定性检查、时间分析、人工结果、报告和独立诊断。

**Blocked by:** 03 — 实现独立时间对齐与逐帧视频—IMU 映射；05 — 实现实际测试 ZIP 导入与安全校验

**Status:** resolved
**Version:** v0.1.0-rc.2

- [x] 导入任务创建后不自动运行，测试工程师必须配置参考时钟、判定模式和阈值后手工启动。
- [x] 导入型运行跳过合成数据生成和故障真值，自动执行所有适用的确定性检查。
- [x] 缺少可选证据时对应检查为未执行，而不是通过或失败；导入型运行不产生故障真值对照指标。
- [x] 导入型运行保留原始输入不可变性，并产生独立的检查、对齐、人工结果、报告和诊断派生结果。
- [x] 运行详情可观察导入来源、校验警告、阶段、取消、异常中断、复测和任务生命周期限制。
- [x] 公开 API 集成测试覆盖手工启动、正常完成、缺证据警告、失败降级、取消和历史证据保护。

## Answer

已完成 RC2 ticket 06 的导入型运行链路：导入任务创建后保持未执行；启动时必须提交参考时钟和判定配置；运行直接引用已入库的不可变原始视频、IMU 和可选设备证据，不调用合成生成器，也不创建 `fault_truth.json`。

导入运行复用了现有视频、六轴 IMU 检查、时间分析、逐帧视频—IMU 映射、人工结果、报告和诊断 seam。缺少设备状态或日志时，相关存储检查为 `not_run`；报告中的故障真值为 `null`；派生映射写入运行目录，不写回导入原始目录。取消、运行失败降级、复测和有运行记录后只能归档的生命周期由现有运行与任务 API 继续提供。
