# 03 — 导入并管理原始测试用例

**What to build:** 让测试工程师在指定产品版本中导入 Beta 产品需求或测试用例资料，经字段映射确认后形成独立导入记录和原始测试用例表。v0.2.0 不创建需求点对象，也不实现需求到用例的完整生成流程。

**Blocked by:** 02 — 建立项目与产品版本工作区。

**Status:** ready-for-agent

**当前前端 Demo 对应页面：** “需求 / 测试用例”中的“测试需求”和“测试用例表”。

- [ ] 导入前展示并允许确认字段映射，覆盖规格约定的常用字段，且“输入”允许为空。
- [ ] 用户可以选择是否导入历史结果、测试记录、测试前备注、计划执行时间和附件。
- [ ] 同一导入记录内原始用例编号唯一；重复导入同一文件产生新的导入记录而不覆盖旧内容。
- [ ] 支持按模块、测试项、优先级和软件版本筛选，并支持全选、反选和勾选。
- [ ] 待加入测试组清单按项目和产品版本持久化，关闭网站后重新打开仍能恢复。
- [ ] `RequirementPointAnalysisService` 和 `TestCaseGenerationService` 具有明确的关闭实现，返回“未启用”且不伪造需求点或测试用例；资料导入不依赖它们。
- [ ] 删除导入记录前展示影响；已有自动化用例保留，并能表达“导入记录已删除”的来源状态。
- [ ] 数据库、导入与查询接口、字段映射页面及筛选/勾选恢复均有自动化测试。
