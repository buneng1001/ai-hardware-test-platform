# 11 — 接入可选报告分析适配器并提供失败降级

**What to build:** 在事实报告完成后，通过 `ReportAnalysisService` 可选生成结构化风险、补充验证、回归建议和阶段推进建议。未配置适配器或分析失败时，事实报告保持完整可用；具体项目 Skill 不属于 v0.2.0 必须交付项。

**Blocked by:** 01 — 平台入口与可选 AI 配置；10 — 生成不依赖 AI 的模块化事实报告。

**Status:** ready-for-agent

**当前前端 Demo 对应页面：** 最终报告中的阶段建议和 AI 分析区域；首页 AI 配置。

- [ ] AI 输入只来自已保存事实报告和有限支撑数据，不读取无关原始日志或凭空补充阈值。
- [ ] 分析输出经过结构化模式校验，不能修改事实状态、测试资产、测试组或数据包。
- [ ] 服务支持未启用实现、项目现有模型服务适配器和固定输出 Mock，并保留未来项目定制适配器位置。
- [ ] 未配置适配器时显示“AI 分析未启用”；超时、不可用或无有效输出时显示“分析未完成”和简短原因。
- [ ] AI 未启用或失败不会回滚、删除或阻止事实报告。
- [ ] 用户可以单独重试报告分析，不重新执行自动化测试或重新录入人工结果。
- [ ] 阶段推进只表达建议及依据，不实现强制质量门禁。
- [ ] 分析运行状态持久化、接口、报告 AI 区域和失败降级均有自动化测试。
- [ ] 每次请求保存 `finish_reason` 与响应长度；`finish_reason=length` 时显示"输出被截断"，不得报成接口不兼容或结构无效。
- [ ] 报告输入按模块分批，每批成功即保存检查点；截断时二分重试，缩减到单模块仍超限时明确失败并给出下一步建议。
- [ ] 每次请求记录 provider、模型、Endpoint 主机名、网络方式、Prompt 版本、批次、耗时、Token 和重试/修复次数（见 AI 接入护栏）。
- [ ] 同一报告与同一配置指纹重复请求时默认复用已完成结果，用户显式重跑才新建运行。
- [ ] 新分析完成后切换为活动结果并立即替换前端视图；后台校准使用 `no-store` 或带运行版本的缓存键。
- [ ] 失败、超时、截断和部分完成状态持久化，页面保留阶段、耗时、诊断和下一步建议。
