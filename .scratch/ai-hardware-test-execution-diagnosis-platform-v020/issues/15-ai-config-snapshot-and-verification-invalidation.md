# 15 — AI 配置快照与验证状态失效

**What to build:** 把 provider、Endpoint、模型、密钥来源和网络方式作为一个整体配置快照持久化，并分别保存模型目录、验证状态和当前选择。任一字段变化后，旧的"已验证"状态立即失效，用户必须重新测试。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 01 — 平台入口与可选 AI 配置

**Status:** ready-for-agent

**当前前端 Demo 对应页面：** 首页 AI 配置卡、服务商与模型下拉框。

- [ ] 配置快照持久化，包含 provider、Endpoint、模型、密钥来源、网络方式和配置指纹；不保存明文密钥。
- [ ] 配置在应用重启后可恢复；读取接口只返回密钥来源与指纹，不返回明文；临时密钥与持久化配置的优先级明确。
- [ ] 提供数据库迁移和迁移测试，已有数据可正常打开，不破坏 v0.2.0 现有数据。
- [ ] 模型目录、验证状态和当前选择分开存储，不能用一个字段表达三种含义。
- [ ] 一次 AI 运行开始时冻结快照，运行期间修改配置只影响下一次运行。
- [ ] provider、Endpoint、模型、密钥来源或网络方式任一变化，旧验证状态立即失效并在界面上提示重新测试。
- [ ] 网络方式支持自动 / 系统代理 / 直连，默认自动；自动模式按"系统代理 → 直连"有限回退，只有连接类错误触发回退，每次回退写入诊断，鉴权与模型错误不回退。
- [ ] 模型 ID 使用服务商返回的精确值，不自动规范化、不猜测别名。
- [ ] 当前选择的模型不在新发现的列表中时给出明确提示，由用户决定，不静默改选。
- [ ] 配置快照、失效规则和迁移均有自动化测试，使用 fake provider，不访问真实服务。

## 边界

- 不做多用户、团队级或组织级配置共享，本版本仍是单用户本机配置。
- v0.2.0 不开放自定义 Endpoint 输入框：Endpoint 由服务商常量或环境变量决定，快照只记录实际使用的值，开放自定义 Endpoint 留给后续版本。
- 网络方式（自动 / 系统代理 / 直连）属于 v0.2.0 范围：默认 `auto`，先系统代理再直连，仅连接类错误回退且每次回退写入运行诊断；设置入口位置与前端冻结稿对齐后确定。
