# 16 — 模型调用错误分类与分层超时

**What to build:** 把现在的单一 30 秒超时和粗粒度错误类型换成可配置的分层超时与结构化错误模型。用户必须能看出是目录查询、连接测试还是业务请求失败，失败属于哪一类，能否重试，下一步做什么。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 15 — AI 配置快照与验证状态失效

**Status:** needs-triage

**当前前端 Demo 对应页面：** 首页连接测试结果、报告 AI 区域的失败提示。

- [ ] 模型目录查询、连接测试和业务请求使用各自可配置的超时，错误信息指明是哪一层超时。
- [ ] 统一错误结构：`stage`、`kind`、`retryable`、`user_message`、`action`、脱敏后的 `diagnostic`。
- [ ] `kind` 至少区分 DNS、TLS、代理、连接失败、鉴权、权限、模型 ID 无效、限流、服务商 5xx、超时、输出截断、响应不可解析和 Schema 校验失败。
- [ ] 只有瞬时错误自动重试：最多一次、退避 1 秒、退避过程可取消、计入调用上限。
- [ ] 鉴权失败、权限不足、模型 ID 无效、确定性 4xx 和 Schema 业务字段缺失一律不重试。
- [ ] 错误与诊断持久化，响应、界面提示和数据库中都不得出现密钥、Authorization 头或完整请求体。
- [ ] fake provider 覆盖上述每种错误类型，并断言输出中不泄露密钥。

## 边界

- 本项目当前是同步请求，不引入流式响应；若后续改流式，需要另加"首个响应等待"和"流式停顿"两档超时。
- 超时默认值（目录与连接测试 20 秒、业务请求 600 秒）为起始值，随服务商和模型能力调整，不写死在代码里。
- 不改动 ADR 0006 关于 AI 不进入测试执行关键路径的结论。
