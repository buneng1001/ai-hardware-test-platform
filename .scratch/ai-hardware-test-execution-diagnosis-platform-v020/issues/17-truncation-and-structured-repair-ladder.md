# 17 — 输出截断识别与结构化修复层级

**What to build:** 让系统能区分"模型输出被截断"和"响应格式不兼容"，并按确定的顺序修复结构化输出：去包装、Schema 校验、本地确定性归一化、最多一次受约束模型修复，最后失败并保留证据。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 16 — 模型调用错误分类与分层超时

**Status:** ready-for-agent

**当前前端 Demo 对应页面：** 报告 AI 区域的失败原因与重试入口。

- [x] 每次请求保存 `finish_reason`、响应文本长度和 Token 用量（服务商提供时）。
- [x] `finish_reason=length` 归类为"输出被截断"，界面明确提示，不得报成"接口不兼容"或"模型未返回合法 JSON"。
- [x] 修复顺序固定：去除 Markdown 围栏等包装 → Schema 校验 → 本地确定性归一化 → 最多一次受约束模型修复 → 失败并标记人工复核。
- [x] 本地归一化只补充能从现有 ID 精确推导的字段（例如证据引用是否存在于本次输入），不得创造业务事实。
- [x] 受约束修复的提示词只包含缺失字段、合法范围和必要错误，不回灌整段失败输出与大量校验上下文。
- [x] 模型修复调用有独立预算并计入总调用上限。
- [x] 测试区分"截断"和"不可解析"两种失败，确认不会互相误报；模型回显修复上下文时能识别并失败。

## 边界

- 不给模型新增、删除或改写业务事实的权限；缺少业务内容时失败或标记人工复核，不自动补全。
- 提高 `max_tokens` 只能作为可配置项，不能替代缩小单批语义范围。
- 自动化用例转换和报告分析共用同一套修复层级，不各自实现一套。

## 2026-10-30 完成记录

- 新增共享结构化修复模块 `structured_repair.py`：去 Markdown/外层包装 → Schema 校验 → 本地只补空证据引用 → 最多一次受约束修复 → 失败并保留步骤与错误。
- 受约束修复提示词只含字段、合法引用范围和脱敏错误，不包含失败输出；修复调用有独立预算并计入适配器总调用上限；模型回显修复上下文标记时直接失败。
- 报告分析接入修复层级；通用结构化输出不再套用诊断字段约束；`finish_reason=length` 继续归类为输出截断，界面显示“模型输出被截断”和下一步。
- 每次请求日志保存 finish_reason、响应长度和 Token 用量。
- 证据：`backend/tests/test_structured_repair.py`（7 项：包装/截断区分、归一化、修复、预算、回显、无预算失败）、`test_ai_error_model.py` 新增请求日志元数据断言、前端 `V020ReportAnalysis.test.tsx` 截断提示测试。后端 195 通过，前端 152 通过 / 3 跳过，`tsc -b`、`vite build`、Prettier、Ruff 与仓库安全检查均通过。
