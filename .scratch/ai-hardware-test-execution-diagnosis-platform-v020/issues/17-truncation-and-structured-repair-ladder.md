# 17 — 输出截断识别与结构化修复层级

**What to build:** 让系统能区分"模型输出被截断"和"响应格式不兼容"，并按确定的顺序修复结构化输出：去包装、Schema 校验、本地确定性归一化、最多一次受约束模型修复，最后失败并保留证据。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 16 — 模型调用错误分类与分层超时

**Status:** needs-triage

**当前前端 Demo 对应页面：** 报告 AI 区域的失败原因与重试入口。

- [ ] 每次请求保存 `finish_reason`、响应文本长度和 Token 用量（服务商提供时）。
- [ ] `finish_reason=length` 归类为"输出被截断"，界面明确提示，不得报成"接口不兼容"或"模型未返回合法 JSON"。
- [ ] 修复顺序固定：去除 Markdown 围栏等包装 → Schema 校验 → 本地确定性归一化 → 最多一次受约束模型修复 → 失败并标记人工复核。
- [ ] 本地归一化只补充能从现有 ID 精确推导的字段（例如证据引用是否存在于本次输入），不得创造业务事实。
- [ ] 受约束修复的提示词只包含缺失字段、合法范围和必要错误，不回灌整段失败输出与大量校验上下文。
- [ ] 模型修复调用有独立预算并计入总调用上限。
- [ ] 测试区分"截断"和"不可解析"两种失败，确认不会互相误报；模型回显修复上下文时能识别并失败。

## 边界

- 不给模型新增、删除或改写业务事实的权限；缺少业务内容时失败或标记人工复核，不自动补全。
- 提高 `max_tokens` 只能作为可配置项，不能替代缩小单批语义范围。
- 自动化用例转换和报告分析共用同一套修复层级，不各自实现一套。
