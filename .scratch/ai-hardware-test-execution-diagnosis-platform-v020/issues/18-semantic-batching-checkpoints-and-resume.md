# 18 — 长输入语义分批、检查点与恢复

**What to build:** 报告分析和自动化用例转换不再一次性把全部输入发给模型。按模块、记录、用例等语义单位分批，每批成功即保存检查点；遇到输出截断时二分重试，恢复到单单元仍超限时明确失败。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 16 — 模型调用错误分类与分层超时

**Status:** ready-for-agent

**当前前端 Demo 对应页面：** 报告 AI 分析进度与失败提示。

- [x] 发送前做预算预检：提示词 Token 与预留输出超过安全预算时直接拒绝并说明原因，不发出请求。
- [x] 按语义单位分批（报告模块、事实记录、用例行），不允许按字符数机械切分。
- [x] 每批成功即保存检查点，运行状态持久化；跨批结果用稳定 ID 关联，不依赖自然语言位置。
- [x] 截断或预算超限且当前批包含多个语义单元时二分重试；缩减到单一单元仍超限时明确失败，提示缩小范围或更换模型。
- [x] 恢复运行只执行未完成范围，已完成批次不重复调用、不重复计费。
- [x] 取消操作在请求、退避和阶段边界都生效，取消后检查点保留。
- [x] 正常调用、瞬时重试和结构修复共享一个可配置的调用硬上限。
- [x] 分批默认值有显式配置项（模块 6、记录 60、用例行 20、输出预留 8,192 Token、调用上限 40），不写死在调用点，并支持单次运行覆盖。
- [x] fake provider 覆盖每个阶段截断、二分成功、单单元失败、恢复、取消和超上限。

## 边界

- 分批参数属于 v0.2.0 范围，默认值：单批模块 6（范围 1～20）、单批记录 60、单批用例行 20、单批预留输出 8,192 Token、单次运行调用上限 40；全部可配置并支持单次覆盖，首次真实运行后按实际用量校准。
- 不引入分布式的后台任务队列；本版本仍在本进程内执行，只要求状态和检查点可恢复。
- 自动化用例转换的分批不得改变"用户修改后标记未校验"的既有规则。

## 2026-10-30 完成记录
