# 19 — 运行指纹幂等与结果激活

**What to build:** 用输入材料、配置快照、模型和 Prompt 版本生成运行指纹。相同指纹已有成功结果时默认复用，用户显式选择重跑才新建运行；新结果保存后切换活动结果，并让前端立即使用本次运行响应，而不是等待可能带缓存的查询接口。详细规则见 [AI 接入护栏](../../../docs/ai-integration-guardrails.md)。

**Blocked by:** 11 — 接入可选报告分析适配器并提供失败降级；15 — AI 配置快照与验证状态失效

**Status:** needs-triage

**当前前端 Demo 对应页面：** 最终报告 AI 分析区域、报告 AI 重试入口。

- [ ] 运行指纹由输入材料、配置快照、模型和 Prompt/Skill 版本生成，并持久化。
- [ ] 相同指纹已有成功结果时默认复用，只有用户显式重跑才新建运行记录。
- [ ] 一次运行成功后依次完成：保存产物、切换活动结果指针、前端用本次运行响应立即替换视图。
- [ ] 后台校准请求使用 `no-store` 或带运行版本的缓存键，不展示上一次运行的陈旧数据。
- [ ] 新结果激活后重置旧的筛选和分页，避免新结果被旧视图条件隐藏。
- [ ] 失败、取消和部分完成的运行持久化，页面不退回"尚未执行"，保留阶段、耗时、诊断和下一步建议。
- [ ] 不同运行的结果不追加到同一张表；运行历史与当前视图分开。
- [ ] 测试覆盖指纹复用、显式重跑、激活顺序、陈旧缓存防护和失败状态保留。

## 边界

- 复用命中时必须在界面上说明"复用了哪一次运行"，不能静默跳过模型调用。
- 指纹不包含密钥明文，只包含密钥来源与指纹。
- 不引入跨用户共享的结果缓存；复用范围限于同一项目中同一输入与配置。
