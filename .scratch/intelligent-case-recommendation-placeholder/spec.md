# V0.3.0｜05 智能测试用例推荐 UI 占位详细 Spec

> 状态：用户已确认 V0.3.0 仅保留可见 UI 占位、具体入口位置和与 AI 补充说明分区的页面结构。本文不构成真实 AI 测试用例推荐业务 Spec，未来推荐业务不在本阶段详细定义，不进入真实业务 To Tickets。

## 1. 本项交付性质

本项在 V0.3.0 仅保留未来「智能测试用例推荐」能力的可见入口。

本项不实现从需求、产品画像或风险信息生成测试用例推荐的真实业务能力，不产生推荐候选，不保存推荐结果，也不将推荐内容接入正式测试用例、自动化候选或测试组。

未来真实推荐能力属于后续 AI 需求分析链路，登记在 `docs/plans/future-development-items.md`，待未来重新开展需求确认与 To Spec。本 Spec 不定义其输入、输出、推荐算法、提示词、数据模型、审核规则或发布流程。

## 2. 现有实现基线与必须保护的功能

| 文件 / 能力 | 当前实现 | 本项约束 |
| --- | --- | --- |
| `frontend/src/V020PrototypeCases.tsx` | 「测试需求」「测试用例表」「自动化用例表」三个工作区页签 | 本项入口建议复用当前工作区，不重构页签结构 |
| `frontend/src/V020RequirementsScreen.tsx` | 测试需求页面外壳；另有第 03 项定义的真实版本级 `ai_context` 输入 | 本项不得把 `ai_context` 误作需求输入或自动触发推荐 |
| `frontend/src/V020SourceCasesScreen.tsx` | 读取和管理当前版本正式原始测试用例；提供 CSV/XLSX 导入 | 正式用例表、导入、筛选、选择、删除等现有功能保持不变 |
| 「AI 生成自动化用例」 | 通过 `convertSourceTestCasesWithAi` 调用现有 AI 转换服务，将正式原始用例转换为自动化候选，并回显转换结果 | 这是 V0.2.0 已有真实功能，不是本项的「智能测试用例推荐」；不得替换、改名、禁用或改变其行为 |
| 「全部转换（无AI）」 | 按现有确定性规则转换自动化候选 | 保持原有行为 |
| 自动化用例校验及测试组联动 | 管理自动化候选、校验结果及测试组资产 | 保持原有行为，不接收本项的虚构推荐结果 |

## 3. 页面入口与交互

### 3.1 入口位置

- **已确认页面分区**：在现有「需求 / 测试用例」工作区的「测试需求」页面分为「需求材料操作区」与独立的「本版本 AI 补充说明」输入区域。两区不得合并为一个文件说明表单。
- **需求材料操作区**：以独立、轻量且可点击的按钮保留「导入需求点」「AI 分析 / 开始解析」「智能测试用例推荐」等未来入口；其中「智能测试用例推荐」名称必须清晰、独立，且与需求相关的未来入口处于同一操作区域。全部按钮在 V0.3.0 只提示「该功能开发中」。
- **版本补充说明区**：作为独立真实功能，正常编辑并明确保存到当前版本的 `ai_context`；不依赖需求导入，且保存说明不自动执行需求分析或生成用例。
- 不新增业务页签、真实推荐结果页或推荐列表；不提前开发需求→分析→用例生成链路。间距、按钮尺寸及视觉细节在不改变上述区域关系和现有功能的前提下随 UI 验收微调。

### 3.2 点击行为

- 入口使用正常产品 UI 样式并允许点击，不使用明显灰色禁用状态。
- 用户点击后只显示统一提示：「该功能开发中」。
- 点击后不跳转页面、不打开弹窗或文件选择器、不显示加载状态、不模拟推荐成功。
- 不论全局 AI 开关状态、当前是否有活动 AI 调用、是否打开产品版本、当前 `ai_context` 内容或正式用例数量，均执行相同的占位提示。
- 本项不是 AI 业务调用，不受 AI 开关门控，不创建 AI invocation，不占用唯一 AI 调用名额。

## 4. 数据、接口与状态边界

- 不新增推荐 API、请求参数、响应模型、数据库表、字段、推荐记录、候选批次或审核记录。
- 不调用模型，不读取项目画像、产品版本 `ai_context`、需求文件、风险数据或历史执行数据。
- 不创建、修改、删除正式原始用例、自动化候选、测试组、执行记录或报告。
- 不产生可供第 06 项审核的真实候选数据；第 06、07 项的占位 UI 不得把本项入口点击误认为已产生推荐结果。
- 不设置推荐任务状态、排队、重试、取消、保存或覆盖逻辑；本项只有一次同步的提示交互。
- 页面刷新、切换项目/版本或重新进入工作区，不产生或恢复任何推荐任务或结果。

## 5. 异常与边界行为

- 占位提示展示失败时，不得回退为调用 AI、导航到其他页面或写入业务数据；允许用户再次点击入口。
- 全局 AI 开启或关闭、AI 配置无效、当前 AI 被其他任务占用，均不改变本项占位提示行为。
- 用户重复点击只重复显示提示，不累积任务、不生成重复数据。
- 不要求对本项进行模型 Mock 或真实模型质量验收，因为不存在模型调用。

## 6. 独立人工验收

### 6.1 验收前置条件

- 使用已有测试项目及至少一个产品版本。
- 准备至少一条正式原始测试用例、一条自动化候选（如当前测试数据具备）及一个测试组。
- 记录验收前正式用例数、自动化候选数和测试组用例关联，作为数据不变的对照。
- 分别准备全局 AI 开启与关闭状态。

### 6.2 验收步骤

| 编号 | 场景 | 操作 | 明确预期 |
| --- | --- | --- | --- |
| R05-01 | 入口与分区呈现 | 进入「需求 / 测试用例」→「测试需求」 | 可见需求材料操作区中的独立轻量「智能测试用例推荐」按钮，并与「本版本 AI 补充说明」编辑保存区明确分开；保持现有 C 方案，不新增页签或推荐结果 |
| R05-02 | 点击提示 | 点击「智能测试用例推荐」 | 仅提示「该功能开发中」；不跳转、不打开文件选择器或结果弹窗、不显示加载或成功状态 |
| R05-03 | AI 开关无关 | 分别在全局 AI 开启、关闭时点击入口 | 均显示相同提示；不发起模型调用、不触发 AI 关闭提示或占用冲突提示 |
| R05-04 | 活动调用无关 | 在其他位置有 AI 调用正在运行时点击入口 | 仍只显示「该功能开发中」；不创建任务、不改变当前活动调用 |
| R05-05 | 无业务数据变化 | 点击前后检查正式用例、自动化候选、测试组及相关记录 | 数据条数、内容、关联关系均不变化 |
| R05-06 | 重复点击与刷新 | 连续点击入口，刷新页面后重新进入 | 每次点击仅显示提示；刷新后没有推荐任务、推荐结果或待审核记录 |
| R05-07 | 正式用例导入回归 | 使用现有「导入用例表」导入 CSV/XLSX | 原有导入预览、确认和保存流程正常，不受本项影响 |
| R05-08 | AI 自动化转换回归 | 使用现有「AI 生成自动化用例」执行已有转换流程 | 原有转换能力仍可正常调用，生成的是自动化候选而非推荐用例 |
| R05-09 | 规则转换回归 | 使用「全部转换（无AI）」 | 既有确定性规则转换正常，不受本项影响 |
| R05-10 | 测试组回归 | 查看并操作既有测试组中的人工/自动化用例 | 两类资产及既有关联不变，不出现本项生成的虚构推荐项 |

### 6.3 自动化测试与回归

- 为占位入口增加组件测试：可见、可点击、显示准确提示。
- 对点击处理增加网络请求断言，确认没有触发推荐 API 或其他 AI 请求。
- 断言入口点击不改变正式用例、自动化候选及测试组数据。
- 回归 `V020RequirementsScreen.test.tsx`、`V020SourceCases.test.tsx`、`V020AutomationCases.test.tsx`、`V020TestGroupCases.test.tsx` 及相关测试组测试。
- 固定测试数据与真实模型证据不适用本项；本项验收证据为 UI 操作记录、网络请求检查及前后数据对照。

## 7. 明确不做

- 从需求、产品画像或风险信息生成测试用例。
- 推荐用例的结构化字段、覆盖策略、优先级、风险映射及质量评估。
- 推荐结果保存、批次管理、重复推荐检测、更新或覆盖。
- 推荐用例的人工审核、确认、驳回、修改及版本管理（属于未来第 06 项）。
- 将推荐用例发布为正式用例、自动化候选或测试组资产（属于未来第 07 项）。
- 任何模型调用、Mock 推荐结果、推荐 API 或数据库变更。

## 8. 已确认的布局与待 UI 验收事项

- 已确认「需求材料操作区」内以独立轻量按钮展示「智能测试用例推荐」，与「导入需求点」「AI 分析」等占位入口同区域；「本版本 AI 补充说明」在另一区域真实保存。不新增业务页签或推荐结果页。
- 仅间距、字体、尺寸和操作区的局部排版随实际 UI 验收调整，不再将入口位置及按钮形式列入待决事项。
