# V0.3.0｜10 人工与自动化用例关联展示详细 Spec

> 状态：既有资产关系、一对多来源关联、表格保真、类型筛选及三个界面的简化关联入口均已确认；异常降级和固定验收矩阵已补齐。本文件是 To Spec 草案，不代表业务功能已实现或验收通过，进入 To Tickets 前仍须统一核验。

## 1. 目标与范围

- 在保持原始测试用例与自动化测试用例**两种独立资产**的前提下，清楚展示它们之间的来源关系。
- 一条原始测试用例允许关联**多条**自动化用例；每条自动化用例都能追溯唯一来源原始用例。
- 原始用例始终保持原始人工资产身份；有关联自动化副本不代表原始记录被转换成自动化资产。
- 不合并两张用例表，不改变现有测试组中人工/自动化用例的独立身份，不覆盖或修改业务数据。

## 2. 已核对的 V0.2.0 实现基线

- `backend/app/automation_test_cases.py`、`backend/app/source_test_cases.py` 负责自动化及来源用例查询和管理。
- 数据库 `backend/app/database.py` 迁移 v18 已移除 `automation_test_cases.source_test_case_id` 的唯一约束，允许一条来源用例关联多个自动化资产；不能误用迁移 v17 的旧唯一约束推断当前数据模型。
- 现有来源用例查询主要提供单个自动化记录 ID 和校验状态，尚不能完整列出全部关联自动化用例；需扩展返回数据或提供按来源查询能力。
- `frontend/src/SourceTestCasesPanel.tsx`、`frontend/src/AutomationTestCasesPanel.tsx`、`frontend/src/TestGroupCasesPanel.tsx`、`frontend/src/TestGroupAutomationScope.tsx` 为主要展示复用位置。
- 现有自动化用例表支持来源用例信息，测试组自动化列表的来源关联展示还需要核对和补齐。

## 3. 已确认的业务规则

1. 原始用例表与自动化用例表继续分开，原有表格列、筛选项及关键操作必须保留；不通过隐藏列、删按钮或缩小控件换取排版空间。
2. 原始用例可以有 0、1 或多条关联自动化用例；必须能识别其关联存在状态与全部关联项，不能只显示第一条而遗漏其余副本。
3. 自动化用例必须能回溯其来源原始用例，并能区分自己的实际校验状态；来源关系本身不等于人工审核成功或技术校验通过。
4. 原始用例表「类型」筛选解释为：
   - 全部：显示所有原始用例；
   - 人工：显示**没有关联自动化副本**的原始用例；
   - 自动化：显示**至少关联一条自动化副本**的原始用例。
   该筛选仅针对原始用例的**关联状态**，不将自动化资产混入原始用例表，也不修改原始用例自身身份。
5. 「类型（人工/自动化）」不同于「测试类型（功能/性能/兼容性/回归测试等）」，必须保留各自筛选含义。
6. 测试组保持既有人工用例与自动化用例的分别关联和执行身份；来源关联仅供查看追溯，不意味着自动入组、自动生成新用例或自动执行。

## 4. 已确认的关联展示方案

- **原始用例表**：在既有行内容区域显示简短的「自动化 ×N」，N 为该原始用例实际关联的自动化资产数量；点击后能查看全部关联用例及其基本信息，并可按现有导航能力打开对应自动化用例。没有关联时不显示无意义的数量徽记。
- **自动化用例表**：保留现有「来源用例」入口，点击可查看/定位原始来源用例。自动化记录身份和校验状态不受链接影响。
- **测试组自动化列表**：在已有行的适当信息区域显示简洁来源链接，不增加额外独立表格列；不删除、隐藏、合并原有列和操作，既有九列布局继续保留。
- 27 寸 4K 和 13 寸笔记本均要保持可读性，遵照 UI spacing tokens，优先换行/重排或局部滚动，不能挤压、覆盖或隐藏关键操作。

## 5. 来源不可用、加载失败与导航降级（验收口径）

- **正常无关联**：只有后端成功返回并确认关联数为 0 时，原始用例行才不显示「自动化 ×N」。关联数量必须统计当前来源用例的全部有效自动化副本，**不只统计当前分页中的行**；只显示一条关联的旧查询实现不满足验收。
- **正在加载或加载失败**：关联信息尚未返回时用轻量加载态，不把未知关联数显示为 0；请求超时/失败时在原位置提示「关联信息加载失败，请重试」，允许重新加载。保留原表格及已有操作，不伪造不存在关联的结论。
- **来源已删除/不可访问**：正常数据库关系使用外键约束，删除来源可能同步删除关联自动化记录；但对迁移数据、旧页面缓存、失效链接或权限变化仍需处理无有效来源的情况。显示「来源用例不可用」等中性提示，禁用无效跳转，不默认定位另一条来源用例，也不在无权限时泄露受限内容。
- **导航**：点击「自动化 ×N」展示全部关联用例的编号/标题及各自校验状态，并可按现有功能定位相应自动化资产；自动化表和测试组自动化列表的来源链接使用实际关联 ID 及所属项目/版本上下文打开原始用例。若目标已经不在当前视图，可通过现有筛选/导航定位，不要求新增独立管理页面。
- **视觉与保真**：原始用例行增加的是轻量数量提示，不改变原记录的执行身份；测试组自动化列表的来源入口放在既有信息区域，不新增第十列、删减原九列或隐藏既有操作。27 寸 4K 和 13 寸笔记本均核查文字换行、容器边距、控件不覆盖以及必要的局部横向滚动。
- **数据安全**：所有点击、筛选及加载只读来源关系；不得为展示关系自动转换用例、创建关联、加入测试组或修改现有校验状态。

## 6. 验收数据、独立矩阵与证据（规格要求，尚未执行）

### 6.1 固定样例

- 同一测试项目和产品版本准备原始来源用例 `S-0`（0 条自动化副本）、`S-1`（1 条副本）和 `S-3`（3 条副本 `A-1/A-2/A-3`，技术校验状态不完全相同）；另准备不同测试类型和不同模块的原始用例。
- 为 `S-3` 的自动化副本准备一个测试组成员关系，并准备**跨页/筛选**情况下仍应完整计数的列表数据。另用 API Stub 模拟来源不存在、无权限、断网/超时、旧列表缓存等异常；这些异常不需要人为破坏数据库外键约束。
- 测试前后固定记录来源表、自动化表、测试组成员数量与主要字段，并分别在 27 寸 4K、13 寸笔记本视口验收。样例 ID 只作测试标识，不作为产品固定值。

### 6.2 独立验收矩阵

| 编号 | 操作/场景 | 明确预期 |
| --- | --- | --- |
| R10-01 | 查看 `S-0`、`S-1`、`S-3` 的原始用例行 | `S-0` 无多余徽记，其他分别显示「自动化 ×1」及「自动化 ×3」，来源用例本身仍保留人工原始资产身份 |
| R10-02 | 点击 `S-3`「自动化 ×3」并打开各项 | 展示完整三条自动化资产的编号、标题、技术校验状态；可逐条跳转，不只显示第一条 |
| R10-03 | 将某条自动化副本放到不同分页或过滤结果之外 | 后端/页面提供的关联总数仍为 3；不会误以当前页可见数替代真实关联数 |
| R10-04 | 原始用例表切换「全部」「人工」「自动化」 | 全部为所有原始用例，人工为零副本，自动化为有副本的原始用例；不把自动化资产行混入来源用例表 |
| R10-05 | 同时使用「类型」和「测试类型」筛选 | 两个概念独立生效，不能将“有自动化关联”误认为测试类型是“自动化测试” |
| R10-06 | 从自动化用例表点击「来源用例」 | 正确定位原始来源 ID，并保留自动化用例自身校验状态；不会打开同标题的错误记录 |
| R10-07 | 在测试组自动化列表点击来源链接 | 正确打开对应原始来源用例；列表仍保持原有九列与所有关键按钮，人工/自动化执行资产不混合 |
| R10-08 | 模拟关联 API 正在加载、超时、返回异常、重试成功 | 未知时不显示伪造的 0；失败提示并可重试；重试后恢复正确的关联数和链接 |
| R10-09 | 模拟来源 ID 已失效、来源不可访问、旧页面缓存 | 提示「来源用例不可用」，无效链接不可点击，不泄露无权限内容，不自动映射到其他来源 |
| R10-10 | 模拟不同项目或不同产品版本中相同标题的来源记录 | 依据真实来源 ID 与归属定位，不跨项目串线、不按标题猜测关联 |
| R10-11 | 分别在 27 寸 4K 和 13 寸笔记本进行查看、展开、筛选和导航 | 字段与关键操作全部可用，不新增列、不遮挡、不以负 margin/控件缩小/隐藏字段解决布局 |
| R10-12 | 展开、点击、筛选前后比对数据库/接口记录 | 来源用例、自动化资产、校验状态、测试组成员、报告及执行记录均未因展示功能而改变 |

### 6.3 可复核证据

- 固定数据夹具及其来源关系（`S-0/S-1/S-3` 与 `A-1/A-2/A-3`）、API 响应中的全量关联数/列表、两侧定位的实际记录 ID、筛选前后数量对照。
- 27 寸 4K 和 13 寸笔记本的界面截图/操作记录、异常提示与重试记录、导航目标及测试组九列保真记录。
- 展示前后只读验证结果（来源行、自动化行、成员关联与校验状态未改）。接口结构、导航路径与查询优化由 To Tickets 结合既有代码确定，不把本章测试设计当成已执行的验收证据。
