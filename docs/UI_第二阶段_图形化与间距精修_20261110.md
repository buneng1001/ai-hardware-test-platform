## 1. 设计约束

- 延续深蓝工业风 C 方案；Logo C、首页约 2:1 品牌/AI 面板比例、独立项目管理页面和 01–05 工作区结构保持不变。
- 不能删除、合并原有控件、操作按钮和表格列。长表格可在自身容器中滚动，不允许通过隐藏字段解决窄屏布局。
- 页面中不得出现相邻独立输入框/下拉框/按钮边框相贴、重叠或覆盖。先尝试换行、加宽容器与局部滚动，不用缩小字体解决。
- 所有图形显示都必须由当前 API 返回的真实记录产生；空状态不产生模拟统计、装饰性通过率或自造“增长百分比”。
- 结果语义：**已完成 ≠ 全部通过**。失败和阻塞均为执行事实；未执行不计入已执行通过率分母。
- oil-ui Skill 调用已尝试，但本会话的远程技能接口返回不可用；当前实现依照此前确认的 C 方案和实际组件结构推进，**不宣称已执行该 Skill 的自动审查**。

## 2. 全局间距 Token

文件：`frontend/src/V020VisualRefinement.css`（在第一阶段 `V020VisualRefresh.css` 之后加载）。

| Token | 数值 | 典型用途 |
|---|---:|---|
| `--ui-space-icon` | 8px | 图标与说明文字、表单标签和输入控件 |
| `--ui-space-control` | 12px | 相邻表单控件、按钮、同组操作 |
| `--ui-space-row` | 16px | 筛选组纵向间距、数据内容之间 |
| `--ui-space-group` | 22px | 不同操作组 |
| `--ui-space-card` | 18px | 卡片之间 |
| `--ui-space-card-inner` | 20px | 卡片/表单内边距 |
| `--ui-space-section` | 28px | 独立业务段落 |
| `--ui-space-page` | 24–40px | 页边距尺寸上限和适配参考 |

基于独立 CSS 覆盖层统一约束：AI 配置字段、项目搜索、原始/自动化用例工具栏、趋势筛选、测试数据筛选、测试组执行器、结果记录、报告及对话框。

**注意**：并非所有继承旧 CSS 的复杂状态都已完成像素级遍历；本次校验覆盖主页面，仍须人工复核各子弹窗和边缘状态。

## 3. 图形组件与数据血缘

| 页面 | 图形形式 | 真实数据来源 | 约束 |
|---|---|---|---|
| 01 版本与趋势 | 每份最终报告的通过率柱形 | `GET /api/projects/{projectId}/trends` 的 `points[].counts.automation/manual` | 两份及以上报告才画变化图；`single` 和 `empty` 维持原状；标记 `current/stale/superseded` |
| 05 自动化执行 | 分段结果条 + 四类图例 | `AutomationExecution.summary` | 不把完成状态当成“全通过” |
| 05 人工测试 | 分段结果条 + 四类图例 | 已选择的人工记录批次 `results[].status` | 不混用其他批次；空记录不显示虚构结果 |
| 05 最终事实报告 | 结果环图与分段条 | `FactReport.snapshot.pass_rate.overall` | 通过率按 `通过/(通过+失败+阻塞)`，不以全部用例为分母；无已执行用例显示“—” |
| 03 测试数据 | 小图标、状态和卡片网格 | `DataPackage`、原有校验状态及来源字段 | 1366px 视口每行 3 张；更宽屏最多 4 张；不虚构数据包 |
| 04 测试组设置 | 三格关联数量信息块 | `TestGroupSummary.source_test_case_count`、`automation_test_case_count`、`data_package_assignment_count` | 数据包分配数不等同于唯一数据包数，不推导出覆盖率 |
| 02 用例管理 | 现有类型/测试类型标签、明确的工具栏间距 | 现有用例实体与筛选条件 | 原有 12 列/9 列等字段均保留，无新增虚构指标 |

组件：`V020ReportTrendChart.tsx`、`V020ResultBreakdown.tsx`。两者均为**纯展示组件**，没有写入、API 请求、状态更改或上传行为。
