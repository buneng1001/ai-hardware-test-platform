# AI 接入护栏

Status: 需求已定义，实现未开始（2026-10-29）
适用范围: v0.2.0 的可选 AI 能力（模型配置、模型发现、连接测试、自动化用例转换、报告分析），以及后续版本的 AI 能力。
来源: 外部项目的 AI 模型接入复盘文档。只采纳适用于本项目的部分；复盘中的长文档需求分析、流式生成等场景在本项目不存在，相关条目已改写或删除。

本项目 AI 能力不进入测试执行关键路径（见 ADR 0006）。本护栏约束的是"AI 不可用或不准确时，系统必须仍然可解释、可恢复"，而不是要求 AI 一定成功。

## 1. 三级验收，不得混用

| 状态 | 含义 | 证据 |
| --- | --- | --- |
| `discovered` 已发现 | 服务商返回了模型列表 | 目录查询成功 |
| `verified` 已验证 | 当前配置能完成一次最小请求 | 连接测试成功 |
| `workflow_validated` 业务流程已验收 | 能在真实输入规模、输出契约和预算内完成一次业务任务 | 一次成功的业务运行 |

规则：

- 三个状态分别保存、分别展示，前端不得把"已发现"渲染成"可用"。
- "连接测试通过"只证明可达、鉴权、模型权限和响应兼容，不证明报告分析或用例转换能完成。
- 任何验收结论都必须能指向具体证据（接口响应、运行记录、测试用例），不能只写"已完成"。

## 2. 配置快照与验证失效

一次 AI 运行必须绑定不可变配置快照，至少包含：

- provider；
- endpoint（含主机名）；
- model；
- 密钥来源（环境变量、临时输入、本地凭据），不保存明文；
- 网络模式；
- Prompt / Skill 版本；
- 运行开始时的配置指纹。

规则：

- 运行期间用户修改配置，只影响下一次运行，不能悄悄改变当前运行。
- 下列任一字段变化，之前的 `verified` 立即失效，必须重新测试：provider、endpoint、model、密钥来源或指纹、网络模式。
- 模型 ID 使用服务商返回的精确值，不自行规范化、不猜测别名、不静默改选其他模型。
- 当前选择不在新发现列表时，明确提示由用户决定，不自动替换。

## 3. 网络模式

支持 `auto`、`system_proxy`、`direct` 三种网络模式：

- `auto` 按固定有限顺序尝试，每次回退都必须记录，不能静默切换服务商、Endpoint 或模型。默认使用 `auto`：先走系统代理，再走直连；只有连接类错误（DNS、TLS、代理、连接超时）触发回退，鉴权、权限、模型 ID 和限流错误不触发回退。
- `direct` 只表示应用不主动使用系统代理，不保证操作系统、公司网络或 VPN 驱动层不介入，说明文案不得夸大。
- 网络方式变化后保留可编辑配置，不清空密钥和模型历史。

## 4. 分层超时

| 层级 | 默认值 | 作用 |
| --- | ---: | --- |
| 模型目录查询 | 20 秒 | 快速失败，避免下拉框长时间无反馈 |
| 连接测试 | 20 秒 | 只验证最小请求 |
| 单次业务请求总时限 | 600 秒 | 给长输出明确上限 |
| 一次业务运行 | 由调用上限、阶段数和取消共同约束 | 不等于单请求超时乘以阶段数 |

- 所有超时必须可配置，默认值随服务商和模型能力调整。
- 超时错误必须指出是哪一层超时，不能统一显示 `timeout` 或"模型负载高"。
- 本项目当前使用同步请求，没有流式生成。若后续引入流式，需补充"首个响应等待"和"流式停顿"两档，不得与总时限合并。

## 5. 输出边界与截断识别

- 每次请求都保存 HTTP 状态、`finish_reason`、响应文本长度和 Token 用量（服务商提供时）。
- `finish_reason=length` 按"输出被截断"处理并明确提示，不得报告为"接口不兼容"或"模型未返回合法 JSON"。
- 不得用延长超时解决截断；也不得只调大 `max_tokens` 而不缩小单批语义范围。
- 所有生成阶段都必须有输出边界，不能只给已知会超长的阶段写特例。

## 6. 长任务：语义分批、检查点、恢复

- 发送前预检：提示词 Token 与预留输出是否超过安全预算，超限直接拒绝并提示。
- 按语义单位分批（报告模块、事实记录、用例行），不按字符数机械切分。
- 每批成功即保存检查点，运行状态持久化，跨批用稳定 ID 关联。
- 遇到截断或预算超限：当前批含多个语义单元时二分重试；缩小到单一单元仍超限则明确失败，提示用户缩小范围或更换模型。
- 恢复时只执行未完成范围，已完成批次不重复调用；取消后检查点保留，不重复计费。
- 正常调用、瞬时重试和结构修复共享一个调用硬上限，默认值见下表，必须可配置。

v0.2.0 默认参数（均可配置，并支持单次运行覆盖；首次真实运行后按实际 Token 用量校准）：

| 参数 | 默认值 | 说明 |
| --- | ---: | --- |
| 单批模块数 | 6 | 范围 1～20，报告分析按模块分批 |
| 单批记录数 | 60 | 事实记录上限，超出继续拆批 |
| 单批用例行数 | 20 | 自动化用例转换分批 |
| 单批预留输出 | 8,192 Token | 与提示词 Token 一起做预算预检 |
| 单次运行调用上限 | 40 | 含正常调用、瞬时重试与结构修复 |
| 瞬时重试次数 | 1 | 退避 1 秒，可取消 |
| 结构修复次数 | 1 | 只修复可确定补全的字段 |

## 7. 结构化输出修复层级

按以下顺序处理，任一步成功即停止：

1. 去除纯包装差异（Markdown 代码围栏、外层 wrapper）。
2. 严格 Schema 校验：类型、必填字段、枚举、ID 范围、数量上限。
3. 本地确定性归一化：只补充能从现有 ID 精确推导的字段（如证据引用是否存在于本次输入）。
4. 最多一次受约束模型修复：提示词只包含缺失字段、合法范围和必要错误，不附带整段失败输出。
5. 仍失败：保留原始输出与诊断，标记人工复核并停止。

禁止：

- 让模型补齐可以由程序推导的字段；
- 让模型"修复"缺失的业务事实（会制造看似合法的幻觉）；
- 把大量校验上下文回灌给模型（模型会原样回显修复包装）。

## 8. 重试与错误模型

只有明确的瞬时错误才自动重试：网络中断、超时、429、可恢复的 5xx。最多重试一次，退避 1 秒，退避过程可取消，并计入调用上限。

不得盲目重试：鉴权失败、权限不足、模型 ID 无效、确定性 4xx、Schema 业务字段缺失。

统一错误结构：

```json
{
  "stage": "catalog | connection_test | conversion | report_analysis | batch:<id>",
  "kind": "dns | tls | proxy | connection | auth | permission | invalid_model | rate_limit | provider_5xx | timeout | output_truncated | malformed_response | schema_validation",
  "retryable": false,
  "provider": "siliconflow",
  "model": "Qwen/Qwen2.5-72B-Instruct",
  "user_message": "可直接展示给用户的说明",
  "action": "下一步建议",
  "diagnostic": "脱敏后的技术诊断"
}
```

错误信息必须让用户知道"发生了什么、能不能重试、下一步做什么"，不能只给一个通用失败提示。

## 9. 幂等与结果激活

- 运行指纹由输入材料、配置快照、模型和 Prompt/Skill 版本生成。
- 相同指纹已有成功结果时默认复用，用户显式选择重跑才新建运行；不得把新结果盲目追加到旧视图。
- 一次运行"成功"包含三件事：保存产物、切换活动结果指针、前端立即用本次运行响应替换视图。
- 后台 GET 只作二次校准，需使用 `no-store` 或带运行版本的缓存键。
- 失败、取消和部分完成的运行必须持久化，页面不能退回"尚未执行"而丢失排障证据。

## 10. 可观测性与脱敏

每次模型请求至少记录：

- provider、model、Endpoint 主机名、网络模式；
- Prompt/Skill 版本、阶段与批次 ID；
- 开始时间、首个响应时间、总耗时；
- 输入/输出/总 Token（服务商提供时）；
- HTTP 状态、`finish_reason`、响应长度；
- 重试次数、修复次数、检查点与取消状态；
- 脱敏后的错误类型和诊断。

禁止记录 API Key、Authorization 请求头、完整请求体或任何包含密钥的内容。

## 11. Mock、规则实现与真实模型

- Mock、规则转换和真实模型结果必须在数据模型和界面上明确标识来源，禁止用固定输出伪装成真实模型成功。
- 未配置 AI 时显示"未启用"，失败时显示"未完成 + 原因"，都不影响确定性流程和事实报告。
- CI 只使用 fake provider 和固定输出 Mock，不读取真实 API Key，不访问真实模型服务。

## 12. 本项目明确不采用的做法

1. 不把"发现了模型"显示成"模型已验证可用"。
2. 不在 provider、Endpoint 或网络模式变化后沿用旧的验证状态。
3. 不把连接测试、单请求和整次运行合并成同一个超时概念。
4. 不用延长超时解决输出截断。
5. 不为某个已知会超长的阶段写特例，所有生成阶段统一有输出边界。
6. 不按字符数机械切分长输入，按模块、记录、用例等语义单位拆分。
7. 不让模型补齐程序能推导的字段，也不让模型修复缺失业务事实。
8. 不对鉴权、权限、无效模型和确定性 Schema 失败盲重试。
9. 不在恢复运行时重复执行已完成批次。
10. 不只确认数据库写入，而忽略活动结果切换和前端刷新。

## 13. 现状与差距（2026-10-29）

| 能力 | 现状 | 差距 |
| --- | --- | --- |
| 模型发现 | 已有实时目录查询和回退列表 | 发现与验证状态未分开持久化 |
| 连接测试 | 已有最小请求测试 | 与业务请求共用 30 秒超时；错误分类粗 |
| 配置快照 | 运行表只记录 provider 与 model | 缺 endpoint、密钥来源、网络模式、Prompt 版本、指纹 |
| 截断识别 | 未读取 `finish_reason` | 截断会被误报为"结构无效" |
| 长输入 | 报告分析一次性发送全部模块 | 无分批、无检查点、无恢复、无调用上限 |
| 结构化修复 | 校验失败直接判失败 | 缺本地归一化和一次受约束修复 |
| 幂等 | 每次请求新建运行 | 无指纹复用，前端激活待联调 |
| 可观测性 | 只保存 provider、模型、输入快照和错误文本 | 缺阶段、耗时、Token、重试与诊断信息 |

## 14. 验收矩阵

### 配置与发现

- 切换 provider 后，旧模型和旧验证状态立即失效。
- Endpoint、密钥来源或网络模式变化后必须重新验证。
- 发现 0 个、3 个、98 个模型时列表均正确，长列表可滚动可搜索。
- 目录查询失败后无需清空配置即可重试。
- 当前模型不在新列表中时给出明确提示，不静默改选。

### 连接测试

- 最小请求成功；DNS、TLS、代理、连接拒绝分别可区分。
- 密钥无效、模型无权限、模型 ID 无效、429、5xx 分别返回对应类型。
- 超时能区分目录查询、连接测试和业务请求。
- 任何错误都不泄露密钥。

### 长任务

- 每个生成阶段都能模拟截断并正确降级。
- 多语义单元截断后二分成功，单单元仍超限时明确停止。
- 可推导字段本地归一化成功，缺失业务事实时不得伪造。
- 瞬时错误按策略重试，鉴权与确定性错误不重试。
- 调用次数不超过硬上限；取消在任意阶段生效。
- 恢复只执行未完成范围，不重复调用已完成批次。

### 持久化与 UI

- 业务请求成功后前端立即替换旧视图，后台校准不使用陈旧缓存。
- 同一输入不重复追加结果；新运行激活后旧筛选与分页不隐藏新结果。
- Mock、规则实现和真实模型结果有明确来源标识。
- 失败后页面保留阶段、耗时、诊断和下一步建议。
