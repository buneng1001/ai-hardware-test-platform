# AI 自动化全栈课程应用映射

本文记录课程知识点在“智能硬件测试执行与诊断平台”中的实际应用。状态只允许使用“已规划、开发中、已实现、已验证”，避免把计划内容描述为已完成能力。

## 状态说明

- **已规划**：已进入设计，但尚未完成代码。
- **开发中**：已有代码，尚未通过验收。
- **已实现**：功能已完成，尚缺完整验证证据。
- **已验证**：已有自动化测试、运行报告或演示证据。

## 明确不纳入首版

- 支付业务练习：与智能硬件主线无关。
- JMeter：首版以 Pytest 和 API 集成测试为主，需要性能压测时再评估。
- Jenkins：首版使用 GitHub Actions；后续可增加 Jenkins 对照实验。
- AI 测试前风险分析和测试用例推荐：v0.1.0 由测试工程师选择场景和参数，AI 只参与运行后的诊断。
- ADB、HTTP、Shell、串口和刷机控制：v0.1.0 不接入真实或模拟设备控制链路。
- 音频、蓝牙和真实 MCAP：v0.1.0 只覆盖视频、IMU、设备状态和日志。
- unittest 与 HTMLTestRunner：项目统一采用 Pytest 和 Allure。
- 复杂 UI 滑块算法：不属于本项目业务范围。

## 维护规则

每完成一个功能，同时更新状态和证据链接。没有可重复验证证据时，不得标记为“已验证”。
