# AI 智能硬件测试执行与诊断平台：面试案例

本文是持续维护的面试方案。开发过程中只记录真实完成的能力，计划功能必须明确标注。

## 一句话介绍

面向多传感器采集设备的本地测试平台，通过合成视频、IMU、设备状态和日志复现 POC/EVT 阶段的数据质量问题，使用确定性规则完成检测，再由大模型基于可引用证据辅助诊断和生成报告。

## 求职定位

主要面向 Python 自动化测试工程师岗位，同时展示智能硬件或嵌入式测试经验。

## 项目来源与合规边界

项目灵感来自个人在多传感器采集设备测试中的通用经验，但采用洁净重写：不复制原公司的代码、Prompt、数据、文档、界面、名称、接口或未公开产品信息。项目使用虚构设备、公开格式和带故障真值的合成数据。

## 要解决的问题

- 没有真实设备时，如何稳定复现视频、IMU、资源和日志异常。
- 如何区分原始时间戳差异、对齐处理效果和最终验收结论。
- 如何让自动化检查提供稳定事实，同时让 AI 发挥归纳和辅助诊断价值。
- 如何把自动化结果与人工检查结果统一汇总，但不覆盖原始状态。
- 如何在模型 API 不可用时仍完成测试和报告。

## 首版范围

- 四路合成视频、一路合成 IMU、设备状态和日志。
- 六个场景：正常、单路掉帧、多路同步漂移、IMU 异常、存储不足、温升关联组合故障。
- 固定偏移校正和线性漂移校正。
- 正式规格、工程目标、版本基线三种判定模式。
- 人工结果录入及 CSV/Excel 导入。
- 硅基流动 AI 诊断与 Mock 模式。
- 应用内报告、独立 HTML、ZIP 证据包和 Allure。

## 技术路线

- 后端：Python、FastAPI、Pytest、SQLite。
- 前端：React、TypeScript。
- 数据生成与分析：FFmpeg、ffprobe、Python 数值生成器。
- AI：硅基流动为默认服务，通过独立适配层调用。
- 持续集成：GitHub Actions，默认使用 Mock 模式。

## 已验证的工程骨架（2026-08-22）

- 已从空仓库建立 FastAPI、React/TypeScript、pnpm 与 SQLite 最小链路。
- 公开 `GET /api/health` 通过真实 SQLite 查询返回服务与数据库状态；本地 Pytest 1 项通过。
- 状态页通过公开 API 展示服务和 SQLite 可用性；本地 Vitest 1 项、TypeScript 检查和生产构建通过。
- 已建立空值 `.env.example`、项目内数据目录、常见密钥与高风险文件扫描及洁净重写人工清单；本地扫描通过。
- GitHub Actions Mock 基线已实现但尚无远端运行记录，因此不宣称 CI 已验证。

## 已验证的采集任务能力（2026-08-22）

- 测试工程师可从页面创建固定为快速模式、正常采集场景的采集任务，任务以 `draft` 状态保存到 SQLite。
- 已保存任务可通过列表或详情 API 重新读取，页面重新加载后可恢复显示，不依赖前端内存保存。
- 前后端都拒绝空白任务名称；后端非法请求不会产生持久化记录，页面返回可理解的中文提示。
- 本地 Pytest 6 项、Vitest 4 项、TypeScript、Ruff、Prettier、Vite 构建及仓库安全扫描通过。
- 当前只完成采集任务配置与查看，不宣称已具备运行记录、任务执行、数据生成或状态迁移能力。

## 核心链路

```text
配置采集任务
  → 生成带故障真值的合成数据
  → 执行确定性检查
  → 分析对齐前指标
  → 执行时间对齐
  → 分析对齐后残差
  → 汇总人工结果
  → 构建诊断证据包
  → AI 结构化诊断
  → 对照故障真值评估诊断
  → 导出报告与证据包
```

## AI 的职责边界

AI 负责归纳异常、提出可能原因、引用证据、说明不确定性并给出复测建议。AI 不控制设备、不修改原始证据、不决定确定性指标，也不能自行发明验收阈值。

## 面试演示脚本

1. 使用正常场景运行快速任务，说明平台不会为了展示 AI 而制造误报。
2. 使用组合故障场景生成四路视频、IMU、资源指标和日志。
3. 展示对齐前偏移、对齐方法及对齐后残差。
4. 展示确定性检查发现的掉帧和丢样事实。
5. 展示 AI 如何引用同期温度、日志和失败指标提出原因与复测建议。
6. 对照故障真值展示命中、漏判和无证据推测。
7. 关闭模型或切换 Mock，证明测试主流程仍可完成。
8. 导出 HTML 和 ZIP 证据包。

## 首版验收标准

- 六个内置场景均可从界面运行。
- 支持快速、标准和自定义数据配置。
- 真实生成短视频、IMU、状态指标和日志。
- 两种时间对齐方法均可执行，并保留对齐前后结果。
- 正常场景不误报，五个故障场景的预期检查均可识别。
- 三种阈值来源产生符合定义的结论。
- 人工结果和自动化结果分别保存并统一展示。
- AI 输出通过 Schema 和证据引用校验，并可对照故障真值评估。
- 模型不可用时仍能完成测试和原始报告。
- HTML、ZIP、Allure 和 CI 产物可验证。
- README 支持面试官在 Mock 模式下复现。
- 仓库不包含原公司资产或敏感信息。

## 待沉淀的重点问题

- 合成视频如何在真实性和运行速度之间取舍。
- 原始偏移、时钟漂移和画面内容不同步如何区分。
- 如何限制 AI 幻觉并验证诊断质量。
- 任务中断后如何保留证据并恢复。
- 如何保证报告可复现且不泄露密钥。
