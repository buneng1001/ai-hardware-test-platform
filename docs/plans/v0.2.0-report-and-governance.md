# v0.2.0 项目治理、完整报告与准入规则

## 目标

把 v0.1.0 的基础任务执行能力整理成可管理的项目、用例、测试组和测试数据流程，并提供可用于版本评审的完整报告。

## 功能模块

### 项目和用例管理

- 新建项目并记录产品、版本、适用范围和测试目标。
- 判断被测产品是否适合当前平台；不适用时给出转交建议。
- 导入、校验和维护已有测试用例。
- 区分测试用例、自动化任务、测试组和测试运行。

### 测试组和数据管理

- 从自动化任务创建测试组。
- 勾选本次需要执行的测试组。
- 管理数据版本、来源、格式、哈希和适用任务。
- 执行前检查测试组、参数、数据和依赖。

### 完整报告和准入规则

- 报告模板、趋势图、异常时间线和测试结论。
- 版本、设备配置和运行结果对比。
- 通过、失败、阻塞和未执行状态统一汇总。
- 质量门禁、失败阻断、准入原因和证据关联。

## 开发任务

1. 定义项目、用例、自动化任务、测试组、数据集和运行记录 Schema。
2. 增加项目适用性判断和具体失败反馈。
3. 实现测试用例导入、测试组创建和执行计划。
4. 增加数据集版本、来源、哈希和完整性管理。
5. 扩展报告模型、趋势图和版本对比。
6. 实现质量门禁和失败阻断规则。

## 验收标准

- 一个项目可以维护多条用例、多项自动化任务和多个测试组。
- 测试组为空、数据缺失、配置错误等问题能返回具体对象、实际值、期望值和修复建议。
- 同一项目的两次运行可以对比，历史结果不被覆盖。
- 失败检查能够触发明确的准入失败结论。

## 不做

本版本不实现 AI 风险分析、设备控制、音频采集和真实设备连接。
