# v0.2.0 最终报告设计

> 状态：设计审阅稿
>
> 本文描述 v0.2.0 的最终报告、趋势分析和版本对比。它不修改当前 v0.1.0 报告接口，也不代表业务代码已经实现。

## 1. 报告的作用

最终报告用于回答三个问题：

1. 本次测试实际覆盖了什么；
2. 各模块实际发生了什么，哪些结果有风险；
3. 当前是否建议进入下一阶段，还需要补充什么验证。

报告提供事实和建议。公司是否推进下一阶段，由公司结合实际情况决定。

## 2. 报告生成入口

最终报告位于“自动化执行与结果”工作区的一个页签中：

```text
自动化结果 | 人工测试结果 | 最终报告
```

用户流程：

1. 从测试组详情点击“执行自动化测试”；
2. 自动化执行完成后，进入自动化结果页并刷新最新状态；
3. 进入独立人工测试页面录入人工结果；
4. 返回执行与结果工作区的“最终报告”页签；
5. 选择一条自动化执行记录和一条或多条人工测试记录；
6. 生成 HTML 和纯文字报告。

报告页不负责录入人工结果，只负责选择记录、生成、查看、下载和清理已经使用的附件。

## 3. 报告输入记录

### 3.1 自动化记录

一次报告最多选择一条自动化执行记录。该记录内部已经包含：

- 执行时的测试组快照；
- 执行时的自动化用例内容；
- 执行时的数据包和用例分配关系；
- 每个用例/数据组合的结果；
- 数据检查结果；
- 关键运行问题；
- 执行模式和执行状态。

### 3.2 人工记录

一次报告可以选择同一测试组、同一产品版本下的一条或多条人工测试记录。

- 多次人工测试记录不自动覆盖；
- 同一用例有多次结果时，分别保留测试时间和记录；
- 没有填写的人工用例显示“未执行”；
- 只有自动化记录或只有人工记录时，也允许生成报告。

### 3.3 记录范围限制

报告只允许合并同一测试组、同一产品版本的记录。不同测试组或不同产品版本使用版本对比功能查看，不直接合并为一份报告。

如果记录和当前测试组配置不一致，生成前提示：

> 当前记录来自历史配置，报告将使用历史快照。

提示不阻塞生成，因为报告本来就应该反映当次执行或录入时的实际状态。

## 4. 报告结构

报告固定按照以下顺序生成：

```text
1. 测试基本信息
2. 阶段推进评估
3. AI 分析
4. 测试范围总览
5. 按模块展示的详细结果
6. 跨模块问题、补充验证和回归建议
```

### 4.1 测试基本信息

展示：

- 项目名称；
- 产品名称和产品版本；
- 测试组名称；
- 报告生成时间；
- 自动化执行时间和执行模式；
- 人工测试记录时间；
- 本次使用的数据包名称和版本/指纹；
- 报告是否包含自动化结果、人工结果或两者。

### 4.2 阶段推进评估

这是整个测试组或产品版本的总体建议，位置固定在报告第二项。

可能的输出：

- 建议进入下一阶段；
- 建议有条件进入下一阶段；
- 建议暂缓并补充验证；
- 信息不足，建议补充验证。

该结论必须附带主要依据，例如模块结果、失败用例、阻塞项、未执行项和结果不一致项。

它是测试评价建议，不是强制质量门禁，也不要求测试工程师在报告页面点击“批准”。

### 4.3 AI 分析

AI 分析只生成建议，不自动修改测试组、用例、数据包或报告事实结果。

内容包括：

- 高风险问题；
- 需要补充验证的内容；
- 结果不一致项；
- 建议回归的用例；
- 下一版本建议保留的必测项；
- 阶段推进建议的依据。

如果 AI 失败，报告仍然生成事实内容。AI 区域显示“本次分析未完成”和简短原因，用户可以单独点击“重试 AI 分析”。

### 4.4 测试范围总览

展示本次报告实际涉及的范围：

- 原始用例数量；
- 自动化用例数量；
- 人工用例数量；
- 涉及模块和测试项；
- 使用的数据包数量；
- 是否包含故障数据。

范围来自用户选择的记录和执行快照，不根据项目中全部用例推测。

### 4.5 模块详细结果

报告按原始用例的“模块”字段分组。模块为空时归入“未分类”。“测试项”作为模块下的细分维度。

每个模块的结构固定为：

```text
模块名称
当前结论（突出显示）
模块范围
自动化结果
人工结果
关键支撑数据
失败和异常用例
结果不一致项
AI 风险和补充验证建议
```

模块开头的“当前结论”必须明显显示，可以使用加粗、颜色和结论标签，但颜色不能作为唯一含义。

模块结论由两层组成：

1. 系统事实结论：根据实际记录汇总通过、失败、阻塞和未执行数量；
2. AI 判断建议：结合失败记录、数据检查和人工备注给出风险及后续建议。

### 4.6 跨模块问题和回归建议

这一部分集中展示影响多个模块的问题，例如：

- 同一数据包在多个模块中产生相同异常；
- 同一用例自动化和人工结果不一致；
- 版本变化导致多个模块共同退化；
- 连接、数据或环境问题使多个用例阻塞。

AI 可以建议回归用例和下一版本必测项，但用户仍然在测试组详情中手动调整测试范围。

## 5. 结果状态和报告表达

| 内部状态 | 报告显示 | 报告含义 |
| --- | --- | --- |
| `passed` | 通过 | 已执行且实际结果符合预期 |
| `failed` | 失败 | 已执行但实际结果不符合预期 |
| `blocked` | 阻塞 | 因环境、连接或数据问题无法完成 |
| `not_run` | 未执行 | 本次没有开始执行 |

故障数据是有效测试输入。故障数据导致用例中的预期检查不通过时，结果应为“失败”，因为系统确实执行了检查并发现实际结果不符合该用例要求。

人工测试缺失时，人工用例直接显示“未执行”，不阻塞报告生成。

自动化和人工结果不一致时：

- 两个结果都保留；
- 标记“结果不一致”；
- 展示双方的测试记录和时间；
- 交给 AI 提示复核方向；
- 不自动判定哪一方正确。

## 6. 支撑数据范围

报告只展示实际存在、能支撑结论的数据，不自动生成没有来源的指标。

### 6.1 数据包支撑

根据用例需求展示，例如：

- 文件是否存在；
- 视频时长、帧数、编码和时间戳；
- IMU 文件是否存在、采样和时间戳是否完整；
- 视频和 IMU 是否对齐；
- 数据是否包含明确故障场景；
- 数据包的标准格式校验结果。

### 6.2 执行支撑

- 用例实际执行数量；
- 通过、失败、阻塞、未执行数量；
- 执行耗时和中断状态；
- 失败用例的实际结果和预期结果；
- 关键运行问题，例如数据缺失、超时、执行中断或服务异常。

### 6.3 人工支撑

- 人工结果；
- 测试记录；
- 测试前备注；
- 测试时间；
- 附件名称和使用状态。

详细原始日志、证据包、哈希码和未影响判断的过程数据不默认放入报告正文。

## 7. 附件和清理

附件与人工测试结果绑定，用户在人工测试页面上传，在报告页查看使用状态。

报告页提供：

- 附件数量和总大小；
- 哪些附件已经被当前报告使用；
- “清理已使用附件”按钮；
- 清理前确认弹窗。

清理后：

- 删除平台保存的原始附件；
- 报告保留人工测试文字结果和附件名称；
- 附件位置显示“已清理”；
- 用户此前下载的本地报告不受影响；
- 未被当前报告使用的附件不删除。

删除在线报告时只删除报告文件和报告记录，不删除自动化执行记录、人工记录或数据包。

## 8. 报告状态和覆盖规则

| 状态 | 触发条件 | 用户可做的操作 |
| --- | --- | --- |
| 未生成 | 尚未生成当前在线报告 | 选择记录并生成 |
| 已生成 | 当前记录未发生变化 | 查看、下载、清理附件、删除 |
| 已过期 | 测试组、数据包、自动化执行或人工结果发生变化 | 查看旧报告或重新生成 |
| 分析未完成 | AI 分析失败但事实报告已生成 | 重试 AI 分析 |

以下变化会标记在线报告过期：

- 测试组成员变化；
- 测试组数据包关联变化；
- 自动化测试再次执行；
- 人工测试结果修改或删除。

重新生成时覆盖当前在线报告。用户已下载的 HTML 和纯文字文件是独立副本，不受在线报告覆盖影响。

## 9. 趋势图

趋势图放在项目详情页，首页不显示。

### 9.1 数据来源

趋势图只统计已经生成最终报告的数据。临时准备状态、没有报告的执行记录和已删除报告不进入趋势。

### 9.2 默认展示

项目详情默认展示整个项目的历史变化：

- 自动化通过、失败、阻塞、未执行数量；
- 人工通过、失败、阻塞、未执行数量；
- 各模块结果变化；
- 版本间结果变化。

### 9.3 筛选

用户可以按以下条件筛选：

- 产品版本；
- 模块；
- 测试组；
- 测试用例。

筛选无结果时显示“当前筛选条件暂无数据”。只有一个报告时显示单个数据点，不强行绘制趋势线。报告过期时保留数据点并标记“报告已过期”。

## 10. 版本对比

版本对比由用户主动选择两个产品版本或两份最终报告，不默认选择“当前版本”和“上一版本”。

对比内容：

- 相同模块的自动化和人工结果变化；
- 通过、失败、阻塞、未执行数量变化；
- 新增或消失的模块；
- 模块当前结论变化；
- 仍未解决的风险；
- 需要回归的用例。

如果两个版本测试范围不同，报告必须明确显示新增、删除和未对齐的范围，不能把缺失用例直接当成通过或失败。

## 11. HTML 和纯文字版本

### HTML

HTML 用于在线查看和下载，支持：

- 模块结论突出显示；
- 表格和状态颜色；
- 结果详情折叠；
- AI 分析和建议分区；
- 模块筛选或页面内定位。

### 纯文字

纯文字版本保留与 HTML 相同的信息顺序和结论内容，使用标题、缩进和状态标签表达层级，不依赖颜色。

## 12. v0.2.0 验收重点

- [ ] 报告可以同时合并自动化和人工记录。
- [ ] 只有自动化或只有人工记录时也可以生成。
- [ ] 报告不因失败、阻塞或人工缺失而阻塞生成。
- [ ] 每个模块开头有突出显示的当前结论。
- [ ] 模块结论有实际结果和支撑数据。
- [ ] 报告按模块字段分组，不使用平台固定模块分类。
- [ ] AI 分析失败时事实报告仍可查看。
- [ ] AI 只能生成建议，不能自动修改测试资产。
- [ ] 可以下载 HTML 和纯文字版本。
- [ ] 报告可以标记过期并重新生成。
- [ ] 删除在线报告不删除底层测试记录和数据包。
- [ ] 附件可以从报告页清理，且清理后有明确状态。
- [ ] 趋势图只出现在项目详情页。
- [ ] 版本对比由用户主动选择比较对象。
