## 三、验收规格完整性（设计完成 ≠ 测试通过）

1. **08 固定 Mock**：已定义主报告、有效辅助、快照无效/跨项目/重复报告、人工/自动化候选、既有重复用例、校验与部分故障等可复现夹具；独立验收场景 **R08-01～R08-20**，覆盖报告筛选、AI 状态、候选结构、来源证据、批量选择、目标应用、失败重试与结果保留。
2. **08 真实模型**：必须在已验证的真实模型配置和脱敏报告条件下，分别验收“仅主报告”和“含辅助报告”路径；不要求确定的标题/用例数，需人工核查事实引用、用例可执行性和风险分析质量。真实模型记录与 Mock 结果不得混用。
3. **08 数据追溯**：当前建议关联项目/主报告/辅助报告/运行输入指纹及调用结果；已应用行关联正式来源/自动化记录、目标版本/测试组、人工确认、技术校验和失败重试，且原报告与旧用例不被覆盖。
4. **10 固定样例**：准备无副本、1 条副本和 3 条副本的来源用例，另以 Stub 模拟删除/无权/加载失败。独立验收场景 **R10-01～R10-12**；记录全量关联数、双向 ID、筛选、九列保真与双屏交互证据。
5. **03 长度边界**：增补 **R03-15** 检查空值、3000 字符通过、3001 字符拒绝及中英文计数一致性；不能前后端分歧或超长自动截断。
6. **01/02/04–07/11**：已有各自规格、场景与无副作用/现有功能回归要求。待 To Tickets 将矩阵落实为具体单测、集成测试、UI 验收与可复核运行记录。
7. **尚未执行**：本文件及各项 Spec 是测试设计和验收门槛；本轮没有运行前后端测试、实际 AI 调用、数据库迁移或设备验收，不能使用“已通过”表述。

## 四、最终裁决记录

**DEC-08-30（2026-11-17 已结案）**：用户同意 08 智能回归作为 01 公共重复执行规则的业务特例。08 同条件重试仍提示可能重复、提供「重新执行／取消」，不显示「覆盖上一次结果」复选框；新建议完整有效且成功保存后替换项目唯一当前建议，失败、超时、取消、中断、校验或保存失败保留旧建议与已应用正式用例。运行中重复执行须先完成原调用取消收尾。08 仍遵守 01 全局运行锁、就地取消和审计，01 其余 AI 业务保留通用重试规则。

**目前没有待用户裁决的跨 Spec 冲突，To Spec 已正式结项。** 规格结项不代表 V0.3.0 业务已开发或验收通过。
