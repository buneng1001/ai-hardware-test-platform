# v0.4.0 模拟设备与自动化执行

## 目标

让自动化用例真正驱动一个没有实体硬件的模拟设备，验证开机、关机、连接、电量、采集服务和故障注入等设备行为。

## 核心架构

```text
声明式测试用例
  → 用例执行器
  → 统一设备能力接口
  → ADB/HTTP/Shell 模拟适配器
  → 模拟设备状态模型
  → 状态变化、命令结果、日志和数据事件
  → Pytest 断言与规则检查
```

## 功能模块

### 用例执行器

- 读取 YAML/JSON 用例。
- 执行前置条件、步骤、参数、超时、重试和断言。
- 保存每一步的命令、返回值、状态快照和时间。

### 模拟设备内核

- 使用组合状态，而不是少量固定状态：电源、连接、录制、服务、电量、存储、网络和版本。
- 支持虚拟时间、状态转换、事件记录和故障注入。
- 保证设备状态、命令返回、日志、资源和采集数据一致。

### 能力和适配器

- 设备能力包括连接、开关机、重启、查询电量、查询存储、查询版本、启动/停止采集和传感器状态。
- ADB、HTTP、Shell 是控制入口，最终访问同一个模拟设备状态。
- Shell 必须使用命令白名单、超时和退出码校验。

## 开发任务

1. 定义用例 Schema 和能力注册协议。
2. 实现模拟设备状态模型与状态转换规则。
3. 实现统一设备能力接口。
4. 实现 ADB、HTTP、Shell 模拟适配器。
5. 将设备状态和事件接入视频、IMU、资源和日志生成器。
6. 接入 Pytest fixture、参数化和证据报告。

## 验收标准

- “开机 → 等待 online → 查询电量”可以完整执行并断言。
- “关机”后 ADB 返回 offline，录制停止并产生关机日志。
- 存储不足会导致录制提前停止、资源指标变化和日志事件产生。
- 同一用例可以切换 ADB、HTTP 和 Shell 适配器。
- 新增能力只需增加能力模块，不修改主执行器。
