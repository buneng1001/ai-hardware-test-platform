## 2. 分类与优先级

分类：

- **缺陷**：现有行为错误、用户无法判断请求状态，或实现内部契约不一致。
- **优化**：现有能力基本成立，但信息架构、文案、反馈或使用说明不足。
- **新需求**：原 SPEC 未要求，或会改变数据契约、领域模型、服务商边界或持久化行为。

优先级：

- **P0**：阻断首版核心能力，必须在 RC2 首先解决。
- **P1**：显著影响正确性、可理解性或重复操作安全，应进入 RC2。
- **P2**：重要体验或数据能力改进，可在 RC2 范围确认后实施。
- **P3**：低风险文案或视觉调整，可与相关垂直切片合并。

证据状态：

- **已确认**：代码、测试或本地 RC1 数据能够直接证明。
- **部分确认**：核心现象有代码依据，但仍缺少完整人工复现证据。
- **设计如此**：当前行为符合原 SPEC，需要解释或决定是否改需求。

### 4.4 第 34 条已确认设计

#### 页面与按钮

- 新增独立的“根据导入生成”标签页，并在页面说明实际测试 ZIP 的结构、必需文件、大小限制和示例。
- 页面提供“导入实际测试文件”“校验导入文件”“转为标准格式”“加入任务列表”四个按钮。
- 未选择 ZIP 时只有导入按钮可用；导入后才能校验；只有校验通过才能加入任务列表。
- “非标准但可转换”时允许点击“转为标准格式”，首版只提示“该功能开发中”。
- 安全风险、文件损坏或其他不可转换错误不能触发转换，也不能加入任务列表。
- 请求执行期间禁用相应按钮，防止重复上传、校验或创建任务。

#### ZIP 与 manifest 契约

- 一次只导入一个 ZIP，不接受单文件或零散多文件上传。
- ZIP 必须包含 `manifest.json`、至少一路视频和一个 IMU 文件。
- 视频支持 1～4 路 H.264 MP4/MKV；manifest 声明通道、帧率、分辨率、码率和时间来源。
- 每路视频不强制提供逐帧旁路文件；平台从容器 PTS 取得逐帧相对时间。
- manifest 必须为每路视频提供 `start_raw_device_timestamp_ns`，用于把容器 PTS 映射到设备原始时钟。
- IMU 支持 CSV/JSONL，至少 100Hz，包含三轴加速度、三轴角速度、原始设备时间和相对时间。
- 加速度单位为 `m/s²`，角速度单位为 `rad/s`。
- `aligned_timestamp_ns` 是平台生成的派生结果，可以为空，且不得覆盖任何原始时间字段。
- 设备状态、设备日志和其他附件可选；实际数据不要求也不允许伪造 `fault_truth.json`。

#### 校验与加入任务列表

- 校验分为安全与结构校验、平台兼容性校验。
- 校验状态分为“通过”“不通过”“非标准但可转换”。
- 错误禁止加入任务列表；警告允许加入并持续显示在任务和报告中。
- 缺少可选设备状态或日志、没有故障真值等属于警告，不属于导入失败。
- 原始 ZIP 的 SHA-256 用于去重；相同 ZIP 不允许重复加入，可跳转到已有任务。
- 文件名相同但哈希不同的数据包视为不同导入。
- 加入后创建 `imported_actual_data` 来源的导入型采集任务，不选择任何合成场景，只填写自由的测试标签。
- 加入任务列表后不自动执行；用户配置参考时钟、判定模式和阈值后手工执行。
- 首版自动运行所有适用的确定性检查，不提供检查项手工选择；缺少可选证据时对应检查标记为未执行。
- 导入型运行没有故障真值，不计算 AI 诊断命中、漏判或无证据推测的真值对照指标。

#### 原始证据、安全和生命周期

- 原始 ZIP 和解压文件不可变保存；运行记录只产生检查、对齐、人工结果、诊断和报告等派生结果。
- 长期保存最小导入凭证：ZIP 哈希、导入时间、校验器版本、最终状态、错误与警告摘要、文件清单与哈希。
- 详细临时扫描日志不长期保存；重新校验可更新当前结果，但首次导入凭证和原始 ZIP 哈希不变。
- 默认限制：ZIP 最大 2GiB、解压后最大 10GiB、最多 100 个文件、单文件最大 5GiB、压缩比不得超过 100:1。
- 上传和解压必须流式写入项目数据目录，校验 ZIP 路径穿越、加密压缩和 ZIP 炸弹风险。
- 上传前必须确认对数据具有处理和展示权限；数据只保存在 Git 忽略的本地目录，不进入仓库。
- 临时隔离区数据默认保留 24 小时并提供手工移除；校验通过后原子移动到正式数据目录。
- 已加入但从未执行的导入型任务可以删除；已有运行记录的任务只能归档，不能删除原始证据。
- “转为标准格式”未来只能从源元数据、可信容器元数据或用户输入取得视频起始设备时间，并记录来源；不得编造绝对时间。

### 4.5 其他范围决定

- RC2 的 AI 服务商范围为硅基流动、DeepSeek 和 Kimi；连接测试、模型选择和错误提示均按当前服务商显示。
- 快速模式 IMU 固定为 100Hz，自定义模式保留 50、100、200、500Hz 等允许值。
- 合成数据和导入数据都采用六轴 IMU，并保留原始设备时间与相对时间。
- 对齐时间不回写原始视频或 IMU 文件，作为独立派生结果保存。
- 对每一路摄像头，以各视频帧时间为基准，从完成时钟变换的 IMU 时间序列中选择时间差最小的样本。
- 因摄像头帧率和 IMU 采样率通常不同，映射必须记录实际时间差和容差判定，不能宣称两个采样点完全同时。
- 逐帧映射建议独立输出为 `frame-imu-alignment.csv`，至少包含视频通道、帧号、视频时间、IMU 样本序号、IMU 时间、时间差、容差和匹配状态；最终字段在正式 spec 中冻结。
- 合成型和导入型采集任务使用相同删除与归档规则：从未执行可删除，已有运行记录只能归档。
- 原始视频提供单独下载；证据 ZIP 默认不包含原始视频，只能显式加入受限小样。

## 7. RC2 范围确认结论

维护者已确认本轮全部范围问题：

1. RC2 增加 DeepSeek 和 Kimi，与硅基流动共同组成多服务商能力。
2. 快速模式 IMU 从 50Hz 改为 100Hz，自定义模式仍允许 50Hz。
3. 合成数据生成器同步升级为六轴 IMU。
4. 合成与导入数据统一保留原始设备时间和相对时间；对齐时间单独派生输出。
5. 合成数据和相关报告同步输出逐视频帧—IMU 最近邻映射，并保留真实时间差。
6. “未执行可删除、已有运行只能归档”同样适用于合成型采集任务。
7. 原始视频提供单独下载；证据 ZIP 默认排除原始视频，仅允许显式包含受限小样。

上述结论连同第 34 条已确认设计，可以进入正式 RC2 spec 整理阶段；本文仍不直接充当 spec 或实施 ticket。
