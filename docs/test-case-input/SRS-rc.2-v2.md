## 1. 目标和范围

GOAL-001：在本机无真实设备环境生成可重复的视频、六轴 IMU、设备状态和日志。

GOAL-002：由确定性检查器先输出指标、故障真值、异常窗口和证据引用，再提供独立 AI 诊断。

GOAL-003：分析原始时间、固定偏移、线性漂移和画面内容同步，保存对齐前后结果。

SCOPE-001：支持 1～4 路 H.264 视频、1 路 IMU、设备状态、设备日志和故障真值。

SCOPE-002：支持 `normal`、`video_drop`、`imu_anomaly`、`storage_exhaustion`、`temperature_combination`、`fixed_offset`、`linear_drift`。

SCOPE-003：支持快速/标准/自定义任务、实际测试 ZIP 导入、运行记录、人工结果、诊断、报告和证据包。

## 2. 用户和基本约束

ROLE-001：测试工程师创建/导入任务、执行/取消/重跑、查看结果、复核锚点、录入人工结果、诊断和导出。

ROLE-002：面试官或复核者查看页面、独立 HTML 或 ZIP，不需要账户。

BR-001：单用户本机运行，同一时刻只有一个运行执行，其他运行排队。

BR-002：平台不使用原公司代码、数据、Prompt、接口、协议、截图或文档。

## 3. 功能需求

### 3.1 任务和生成

FR-001：创建任务必须提供名称、模式和场景，任务初始状态为 `draft`。

FR-002：名称首尾空白去除，长度 1～80；忽略大小写的重复名称拒绝创建。

FR-003：快速模式为 2 秒、2 路 `640x360`/30 FPS/3000 kbps/MP4/H.264、CSV/100 Hz、种子 20260822。

FR-004：标准模式为 5 秒、4 路 `1280x720`/30 FPS/6000 kbps/MP4/H.264、CSV/200 Hz、种子默认 20260822。

FR-005：自定义模式必须提供时长、视频、IMU 和随机种子；时长 2～300 秒，通道 1～4。

FR-006：分辨率为 `640x360`、`1280x720`、`1920x1080`；FPS 为 15/24/25/30/60/120。

FR-007：码率为 100～50000 kbps 且为 100 的倍数；码率模式为 CBR/VBR；容器为 MP4/MKV，编码固定 H.264。

FR-008：IMU 格式为 CSV/JSONL，采样率为 50/100/200/500 Hz，随机种子范围为 0～2147483647。

FR-009：参考通道支持 `camera_1`～`camera_4` 和 `imu`；相机参考通道必须存在。

FR-010：执行前按最多 5 秒实际媒体时长和 600000000 像素帧限制预计文件规模。

FR-011：生成视频、六轴 IMU、设备状态 CSV、设备日志和 `fault_truth.json`，保存路径、来源、大小、SHA-256。

FR-012：检查器覆盖视频、IMU、资源、日志和存储，输出状态、指标、异常窗口、真值对照和证据引用。

FR-013：运行保存配置快照、阶段事件、产物、生成元数据、检查、对齐、判定、人工结果、诊断和错误。

### 3.2 任务、运行和历史

FR-014：已保存任务支持来源、执行状态、归档状态筛选，每页最多 10 条并返回总数。

FR-015：任务卡显示名称、归档标记、来源、运行次数、创建时间，以及每次运行的 ID、执行序号和状态。

FR-016：每次执行产生不可覆盖的新运行记录；运行 ID 可打开运行详情。

FR-017：从未执行任务可删除；有运行记录的任务只能归档；归档任务不可执行或删除，但可查看和导出。

FR-018：支持排队、执行中取消、终态重跑和应用重启后的异常中断识别。

FR-019：用户可隐藏当前页面的单条运行记录；隐藏不得删除后端记录和证据。

### 3.3 对齐、判定和人工结果

FR-020：支持固定偏移锚点校正和多事件线性漂移回归，默认参考通道为 `camera_1`。

FR-021：自动识别视频事件和 IMU 冲击峰值锚点，允许修改检测时间和纳入状态。

FR-022：保存原始时间、对齐前后指标、方法参数、残差、漂移趋势、锚点详情和内容同步。

FR-023：生成逐视频帧到最近 IMU 样本的映射，保存两侧时间、时间差、容差和匹配状态。

FR-024：支持 `requirements_acceptance`、`engineering_target`、`baseline_analysis` 及对应阈值来源。

FR-025：支持人工检查项 CRUD、passed/failed/blocked/not_run、实际结果、备注、执行时间、附件和 CSV/XLSX 导入。

### 3.4 导入、报告和诊断

FR-026：支持实际测试 ZIP 上传、权限确认、校验、重复导入检测和校验后创建任务。

FR-027：提供运行详情、`report.json`、独立 HTML、原始视频下载和可验证 ZIP。

FR-028：ZIP 默认不含原始视频；显式请求时每路最多 1 秒、单文件 5 MiB、总量 10 MiB，并生成缩略图。

FR-029：诊断证据有稳定编号和 32 KiB/4000 estimated tokens 上限；输出为 Schema 校验 JSON。

FR-030：支持 Mock、硅基流动、DeepSeek、Kimi；服务商 Key、端点和模型相互隔离。

FR-031：模型错误不得影响测试运行、确定性检查和原始报告；临时错误最多自动重试两次。

FR-032：仪表盘显示运行统计、近期失败、诊断计数和 AI 评估摘要。

## 4. 业务规则和异常

BR-003：运行正常流转：`queued` → `generating_data` → `running_checks` → `summarizing_results` → `completed`。

BR-004：执行错误为 `failed`，取消为 `cancelled`，重启恢复为 `interrupted`；四者均为终态。

BR-005：终态不可取消；重跑复制配置快照并生成新运行 ID，原记录保留。

BR-006：运行与诊断状态独立；诊断状态为 pending、generating、completed、failed 或 retryable。

BR-007：故障真值在生成阶段确定；AI 不修改真值、确定性检查或验收阈值。

BR-008：只允许 `max_failed_checks` 和 `max_alignment_residual_ms`；阈值非负，前者为整数。

BR-009：证据引用必须存在；没有证据支持的原因必须 `is_speculation=true`。

EX-001：未知任务、运行、导入、人工结果或附件返回 404。

EX-002：非法字段、越界参数、未知场景/模型/锚点、阈值来源不匹配返回 422。

EX-003：有运行任务删除、终态取消、未完成证据导出、无对齐结果复核等操作返回 409。

EX-004：ZIP 超过 2 GiB、人工导入超过 2 MiB、附件超过 1 MiB 或视频样本超限时拒绝。

EX-005：人工文件表头严格为 `name,status,actual_result,notes,executed_at`；导入错误包含行号、字段和原因。

EX-006：附件仅允许 TXT/PNG/JPEG/PDF；导出发现 Key、Token、认证头或敏感二进制标记时拒绝。

## 5. 非功能、验收和非目标

NFR-001：相同配置和种子产生可比较的产物指纹、时间契约和检查输入。

NFR-002：运行、事件、产物、真值、检查、诊断和导出可由 ID、路径或 SHA-256 关联。

NFR-003：HTML 可脱离应用打开；ZIP 有 manifest 和 SHA-256，可独立复核。

NFR-004：Key 不进入仓库、数据库、日志、HTML 或 ZIP；临时 Key 只存于当前会话内存。

NFR-005：后端使用 Python/FastAPI/SQLite/FFmpeg/ffprobe，前端使用 React/TypeScript，依赖使用 pnpm。

AC-001：七种场景可创建运行，正常场景不误报，故障和对齐场景命中预期检查。

AC-002：任务模式、边界参数、任务分页、运行序号、删除/归档边界可验证。

AC-003：运行阶段、取消、重跑、重启中断、配置快照、产物哈希和历史保留可验证。

AC-004：对齐、锚点复核、逐帧映射、三种判定模式和人工结果可验证。

AC-005：ZIP 校验、报告、默认排除视频、显式小样、manifest 和哈希可验证。

AC-006：Mock 诊断结构和证据引用有效；模型失败不影响原始运行。

NONTARGET-001：不接入真实硬件，不实现设备控制、刷机、串口、蓝牙、音频或真实 MCAP。

NONTARGET-002：不建设多人账户、权限、审批、团队协作或复杂用例管理。

NONTARGET-003：不实现复杂非线性时间扭曲，不以删除任务级联删除运行证据。
