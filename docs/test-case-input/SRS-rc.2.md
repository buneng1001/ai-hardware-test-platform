# v0.1.0-rc.2 软件需求规格（SRS）

## 0. 基线与编号规则

- 本文描述 `v0.1.0-rc.2` 应实现的产品行为，不描述实现偏差。
- 仓库未创建可解析的 `v0.1.0-rc.2` Git 标签；本文依据 `SPEC.md`、ADR、`docs/rc2-feedback-triage.md` 和已确认的 RC2 范围整理。
- 代码实际基线为提交 `f80e7b39035e0908b5192a766bf771f67b10774d`；之后的 `v0.1.0` 只更新版本元数据。
- 编号前缀：`GOAL` 目标、`SCOPE` 范围、`ROLE` 角色、`FR` 功能、`BR` 业务规则、`EX` 异常、`NFR` 非功能、`AC` 验收、`NONTARGET` 非目标。
- 无法证实的内容标记为“未确认”，不能作为验收事实。

## 1. 产品目标和范围

GOAL-001：在无真实设备和公司数据的本机环境中，生成可重复的视频、IMU、设备状态和日志数据。

GOAL-002：由不依赖 AI 的确定性检查器先输出事实、指标、异常窗口、故障真值和证据引用。

GOAL-003：分析多路视频与 IMU 的原始时间、固定偏移、线性漂移和画面事件同步，并保留对齐前后结果。

GOAL-004：提供限量、可引用、可评估的结构化 AI 诊断；模型不可用时不阻断测试和原始报告。

SCOPE-001：支持 1～4 路 H.264 视频、1 路六轴 IMU、设备状态、设备日志和故障真值。

SCOPE-002：支持 `normal`、`video_drop`、`imu_anomaly`、`storage_exhaustion`、`temperature_combination`、`fixed_offset`、`linear_drift` 七种场景。

SCOPE-003：支持快速、标准、自定义三种合成任务模式和实际测试 ZIP 导入型任务。

SCOPE-004：支持任务保存、筛选、分页、运行追溯、删除/归档、运行详情、人工结果、诊断、报告和证据导出。

## 2. 用户角色和运行约束

ROLE-001：测试工程师负责创建/导入任务、选择参数、执行/取消/重跑、查看结果、复核锚点、录入人工结果、诊断和导出。

ROLE-002：面试官或复核者通过本地页面、独立 HTML 或 ZIP 查看结果，不需要账户。

BR-001：系统是单用户本机应用；同一时刻只执行一个运行，其他运行排队。

BR-002：不得使用或复刻原公司代码、数据、Prompt、接口、协议、截图或文档。

## 3. 功能需求

### 3.1 任务和数据配置

FR-001：创建任务必须提供名称、模式和场景，新任务状态为 `draft`。

FR-002：名称首尾空白需去除，长度为 1～80；忽略大小写后的重复名称拒绝创建。

FR-003：快速模式为 2 秒、2 路 `640x360`/30 FPS/3000 kbps/MP4/H.264、CSV/100 Hz、随机种子 20260822。

FR-004：标准模式为 5 秒、4 路 `1280x720`/30 FPS/6000 kbps/MP4/H.264、CSV/200 Hz、随机种子默认 20260822。

FR-005：自定义模式必须提供时长、视频、IMU、随机种子；可选七种场景和合法参考通道。

FR-006：时长 2～300 秒；通道 1～4；分辨率为 `640x360`、`1280x720`、`1920x1080`。

FR-007：FPS 支持 15/24/25/30/60/120；码率 100～50000 kbps 且为 100 的倍数；码率模式为 CBR/VBR；容器 MP4/MKV，编码固定 H.264。

FR-008：IMU 格式为 CSV/JSONL，采样率为 50/100/200/500 Hz，随机种子为 0～2147483647。

FR-009：参考通道支持 `camera_1`～`camera_4` 和 `imu`；相机通道必须存在。

FR-010：执行前按最多 5 秒实际媒体时长和 600000000 像素帧限制预计文件规模。

### 3.2 生成、检查和运行

FR-011：每个内置场景定义可复现输入、故障真值和预期检查结果。

FR-012：生成视频、六轴 IMU、设备状态 CSV、设备日志和 `fault_truth.json`，保存路径、来源、大小、SHA-256 和必要的原始设备时间。

FR-013：检查器覆盖视频、IMU、资源、日志、存储，输出状态、指标、异常窗口、真值对照和证据引用。

FR-014：运行保存配置快照、阶段事件、产物、生成元数据、检查、时间分析、判定、人工结果、诊断和错误。

FR-015：运行状态支持排队、生成、检查、汇总、完成、失败、取消和异常中断；终态重跑创建新记录。

### 3.3 已保存任务和历史追溯

FR-016：已保存任务支持来源、执行状态、归档状态筛选；每页最多 10 条并返回总数。

FR-017：任务卡显示名称、归档标记、来源、是否执行过、运行次数、创建时间和每次运行的编号/状态。

FR-018：每次执行产生不可覆盖的新运行；任务内执行序号从 1 递增，运行记录可作为链接打开。

FR-019：从未执行任务可删除；已有运行记录的任务只能归档；归档任务不能执行或删除，但可查看和导出。

FR-020：用户可在当前页面隐藏不需要的运行记录；隐藏不应删除后端记录或证据。

### 3.4 时间分析、判定和人工结果

FR-021：支持固定偏移锚点校正和多事件线性漂移回归，默认参考通道为 `camera_1`。

FR-022：自动识别视频事件和 IMU 冲击峰值锚点，并允许人工修改检测时间和纳入状态。

FR-023：保存原始时间、对齐前后指标、方法参数、残差、漂移趋势、锚点详情和内容同步结果。

FR-024：生成逐视频帧到最近 IMU 样本的映射，保留两侧时间、时间差、容差和匹配状态。

FR-025：支持 `requirements_acceptance`、`engineering_target`、`baseline_analysis` 三种判定模式及对应阈值来源。

FR-026：支持人工检查项 CRUD、四种状态、实际结果、备注、执行时间、小型附件和 CSV/XLSX 导入。

### 3.5 导入、报告和 AI

FR-027：支持上传实际测试 ZIP、权限确认、校验、重复导入检测和创建导入型任务。

FR-028：提供运行详情、JSON 报告、独立 HTML、原始视频独立下载和可验证 ZIP 证据包。

FR-029：ZIP 默认不含原始视频；显式请求可加入每路最多 1 秒、单文件 5 MiB、总量 10 MiB 的小样，并生成缩略图。

FR-030：诊断证据使用稳定编号并受大小/Token 限制；诊断输出为 Schema 校验 JSON，包含现象、原因、引用、置信度、影响、复测、缺失证据、不确定性和限制。

FR-031：支持 Mock、硅基流动、DeepSeek、Kimi，服务商的 Key、端点和模型必须隔离。

FR-032：模型错误不得改变测试运行、确定性检查和原始报告；仅临时错误最多自动重试两次。

FR-033：仪表盘展示运行统计、近期失败、诊断计数和 AI 评估摘要。

## 4. 业务规则与状态流转

BR-003：正常运行流转为 `queued` → `generating_data` → `running_checks` → `summarizing_results` → `completed`。

BR-004：执行错误进入 `failed`，取消进入 `cancelled`，应用重启时非终态进入 `interrupted`。

BR-005：`completed`、`failed`、`cancelled`、`interrupted` 为终态；终态不可取消，重跑产生新 ID。

BR-006：运行与诊断状态独立；诊断状态为 `pending`、`generating`、`completed`、`failed`、`retryable`。

BR-007：确定性生成和检查先于诊断；故障真值由生成阶段确定，AI 不得修改。

BR-008：只允许 `max_failed_checks` 和 `max_alignment_residual_ms`，阈值非负；前者必须为整数。

BR-009：证据引用必须存在；无证据原因必须标记 `is_speculation=true`。

## 5. 异常与边界条件

EX-001：未知任务、运行、导入、人工结果或附件返回 404。

EX-002：非法字段、未知场景、越界参数、阈值来源不匹配、未知模型或锚点返回 422。

EX-003：有运行记录的任务删除、终态取消、导入转换等冲突操作返回 409。

EX-004：非完成运行不能导出完整证据；无对齐结果不能复核；有效锚点不足返回 422。

EX-005：ZIP 超过 2 GiB、人工导入超过 2 MiB、附件超过 1 MiB、视频小样超限时拒绝。

EX-006：人工 CSV/XLSX 必须 UTF-8/UTF-8 BOM，表头严格为 `name,status,actual_result,notes,executed_at`；错误须指出行号、字段和原因。

EX-007：附件仅允许 TXT、PNG、JPEG、PDF；名称最多 120 字符，结果和备注各最多 2000 字符。

EX-008：导出发现认证头、Token、API Key 或敏感二进制标记时拒绝；数据库不可用时健康检查返回 503。

## 6. 非功能需求

NFR-001：相同配置和随机种子应产生可比较的产物指纹、时间契约和检查输入。

NFR-002：运行、事件、产物、真值、检查、阈值、诊断和导出文件可通过 ID、路径或 SHA-256 关联。

NFR-003：HTML 可脱离应用打开；ZIP 有 manifest 和哈希，可独立复核。

NFR-004：Key 不得进入仓库、数据库、日志、HTML 或 ZIP；临时 Key 只存在当前会话内存。

NFR-005：AI 不进入测试关键路径；Mock 可离线运行并用于自动化验收。

NFR-006：后端使用 Python/FastAPI/SQLite/FFmpeg/ffprobe，前端使用 React/TypeScript，依赖使用 pnpm。

NFR-007：单机执行有文件规模和视频样本保护；长时场景须标记虚拟时间来源。

NFR-008：生成、导入和导出文本使用 UTF-8；证据 CSV 使用 UTF-8 BOM；路径限制在数据目录内。

## 7. 可验证验收标准

AC-001：七种场景均可创建运行；正常场景不误报，故障/对齐场景命中预期检查。

AC-002：快速、标准、自定义及边界参数通过 API/页面验证；非法配置不入库。

AC-003：已保存任务支持筛选、10 条分页、运行次数、每次运行链接、删除和归档边界。

AC-004：可观察排队、阶段、取消、终态重跑和重启后的 `interrupted`，历史不被覆盖。

AC-005：运行含配置快照、产物哈希、来源、真值、检查、事件和任务内执行序号。

AC-006：两种对齐方法、锚点复核、逐帧映射、对齐前后指标和内容同步可验证。

AC-007：三种判定模式的阈值来源、优先级和结论语义符合 BR-008。

AC-008：人工结果可增改、导入、下载附件，并与自动检查分别保存、统一报告。

AC-009：实际 ZIP 可校验、拒绝不安全输入、保留导入证据并支持人工配置后运行。

AC-010：Mock 诊断结构和引用有效，能统计命中/漏判/无依据推测/误报；模型失败不影响原始运行。

AC-011：HTML 可独立打开；默认 ZIP 不含原始视频，manifest、SHA-256、缩略图和显式小样规则可复核。

AC-012：自动化测试、安全检查和 README 验收路径可执行；真实线上模型、真实设备和远端 CI 结果不作为已验证事实。

## 8. 明确非目标

NONTARGET-001：不复刻原公司产品、协议、界面、流程或资产。

NONTARGET-002：不接入真实硬件，不实现设备控制、刷机、串口、蓝牙、音频或真实 MCAP。

NONTARGET-003：不建设多人账户、权限、审批、团队协作或复杂用例管理。

NONTARGET-004：AI 不控制设备、不修改事实、不决定确定性检查结果、不生成验收阈值。

NONTARGET-005：不实现复杂非线性时间扭曲；不以删除任务级联删除已有证据。
