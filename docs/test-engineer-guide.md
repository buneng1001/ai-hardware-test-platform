# 测试工程师使用手册

本文面向本地运行平台的测试工程师，说明每个配置项会产生什么效果、如何选择场景、如何导入实际数据，
以及如何判断、复核和导出一次运行。平台只使用虚构设备、公开格式和合成数据；不要把公司数据或未获授权的实际数据放入仓库。

## 1. 启动平台

先按 README 的“环境准备”安装依赖，再分别启动后端和前端：

```powershell
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --env-file .env
pnpm --dir frontend dev
```

浏览器打开 `http://127.0.0.1:5173`。默认使用 Mock 模式，不需要真实 API Key。

## 2. 页面和基本工作流

平台的页面或标签含义如下：

| 页面 | 用途 |
| --- | --- |
| 仪表盘与AI配置 | 查看运行统计、近期失败和诊断状态，并配置 AI 服务商和模型 |
| 新建任务 | 创建合成型采集任务 |
| 根据导入生成 | 上传、校验实际测试 ZIP，并创建导入型采集任务 |
| 已保存任务 | 按来源、运行状态和归档状态筛选任务，每页最多 10 条 |
| 运行详情 | 查看阶段、产物、检查、对齐、人工结果、诊断和导出 |

推荐流程是：创建或导入任务 → 检查配置 → 手工启动运行 → 查看确定性检查 → 查看时间分析 → 录入人工结果 →
按需运行 AI 诊断 → 导出报告和证据。

## 3. 仪表盘与AI配置

### 3.1 仪表盘

“仪表盘”是打开系统后看到的运行总览。它把已经保存或执行过的运行汇总成少量状态，帮助测试工程师决定下一步查看哪一次运行，
而不是用来创建任务、修改配置或替代运行详情。

仪表盘显示三类信息：运行总数及已完成/失败数量、诊断完成/失败数量、AI 评估中的命中/漏判/无证据推测数量。
“近期失败”列表会显示任务名称、运行编号、场景、失败检查数量和最近诊断状态。

仪表盘的局限：它只显示汇总状态，不展示完整检查指标、时间对齐参数、人工结果或证据内容；AI 评估是辅助信息，Schema 通过不等于诊断正确，
也不等于确定性检查结果或故障真值。需要确认原因时，必须进入对应的运行详情。

### 3.2 刷新仪表盘

| 操作 | 作用 | 不会做什么 |
| --- | --- | --- |
| 刷新仪表盘 | 重新读取运行统计、诊断汇总和近期失败 | 不会重新执行任务、生成诊断或修改历史运行 |
| 近期失败中的运行按钮 | 打开该运行的运行详情 | 不会重跑该运行，也不会自动生成 AI 诊断 |

如果近期失败没有最新记录，先点击“刷新仪表盘”；如果列表中已有目标运行，直接点击该运行按钮查看详情。

### 3.3 AI 配置

AI 配置是首页右侧的第二个模块，用来决定“运行详情中的结构化诊断”是否调用外部模型、调用哪一家服务商和哪一个模型。
它不会参与视频/IMU 数据生成、确定性检查、时间对齐或正式判定。只有测试工程师明确点击“生成 Mock 诊断”或“生成真实模型诊断”时，
运行详情才会发起诊断请求；打开页面、刷新仪表盘和执行任务不会自动调用 AI。

是否加入 AI 的判断方式：如果只需要可重复的采集、检查、对齐和报告验收，可以只使用 Mock（离线）；如果需要模型归纳异常现象、
整理可能原因和给出复测建议，再配置服务商和模型。AI 结果必须结合检查证据人工复核，不能代替正式测试结论。

#### 3.3.1 诊断模式

“诊断模式”下拉框提供以下选项：

| 模式 | 是否调用外部模型 | 预设模型 | 用途 |
| --- | --- | --- | --- |
| Mock（离线） | 否 | 不需要模型 | 离线演示、回归测试；不产生外部请求 |
| 硅基流动 | 是 | `Qwen/Qwen2.5-72B-Instruct`（默认）、`zai-org/GLM-5.2`、`zai-org/GLM-4.5V`、`Pro/moonshotai/Kimi-K2.6`、`MiniMaxAI/MiniMax-M2.5`、`deepseek-ai/DeepSeek-V3.2`、`Qwen/Qwen3.6-27B`、`Qwen/Qwen3.5-27B`、`Qwen/Qwen3-8B` | 通过硅基流动调用其模型目录中的模型 |
| DeepSeek | 是 | `deepseek-v4-flash`（默认）、`deepseek-v4-pro` | 通过 DeepSeek 接口调用 DeepSeek 模型 |
| Kimi | 是 | `kimi-k2.6`（默认）、`kimi-k2.5`、`kimi-k2.7-code` | 通过 Kimi 接口调用 Kimi 模型 |

除了 Mock（离线）以外，必须选择一个预设模型，或选择“自定义模型”后输入完整模型标识；如果需要其他模型厂商或当前列表之外的模型，
请联系开发者确认接口和模型 ID。切换模式会清空当前页面的连接提示和临时 API Key，但不会修改 `.env`。

#### 3.3.2 模型

在硅基流动、DeepSeek、Kimi 模式下，模型通过下拉框选择，也可以选择“自定义模型”后输入完整模型 ID。
如果当前选择的是 Mock（离线），页面不会显示模型下拉框，因为该模式不调用模型；切换到其他三种模式后才会显示。
模型是否可用以连接测试或诊断请求的返回结果为准。

#### 3.3.3 临时 API Key

“临时 API Key”是本次浏览器页面会话中临时使用的密钥：

- 填写临时 Key 后，点击“测试 AI 连接”会优先使用临时 Key；
- 临时 Key 留空时，“测试 AI 连接”会回退使用后端本地配置；
- 切换诊断模式后，临时 Key 会被清空；
- 后端不会返回、掩码、保存或写入报告中的 Key。

该值没有写入 Cookie、localStorage、数据库或 `.env`。刷新页面、关闭页面、重新打开页面、浏览器进程重启以及后端重启后，临时 Key 都不会保留，
需要重新输入；本地配置文件位于项目根目录：

```text
D:\0_Project\Work_Case\ai-hardware-test-platform\.env
```

后端通过启动命令中的 `--env-file .env` 读取它。`.env` 只保存在本机，不应提交到 Git；修改后必须完全重启后端才会生效。

#### 3.3.4 测试 AI 连接

“测试 AI 连接”会实际请求当前选择的服务商和模型。结果会显示：

```text
当前可用｜来源：临时 API Key｜siliconflow/Qwen/Qwen2.5-72B-Instruct：连接可用
```

如果临时 Key 为空，结果会明确显示使用本地配置回退。该按钮用于验证当前页面输入的 Key，可能消耗服务商额度；Mock 模式不调用模型。

#### 3.3.5 使用本地配置测试

“使用本地配置测试”会忽略页面临时 Key，强制使用后端环境变量中的 Key，例如：

| 服务商 | 环境变量 |
| --- | --- |
| 硅基流动 | `SILICONFLOW_API_KEY` |
| DeepSeek | `DEEPSEEK_API_KEY` |
| Kimi | `KIMI_API_KEY` |

该按钮会读取后端配置状态，并忽略页面临时 Key，强制使用当前服务商对应的环境变量，再实际调用当前模型。
Mock 模式下不需要本地 Key，因此按钮不可用。

#### 3.3.6 状态和错误提示

结果最后一行会突出显示“当前可用/当前不可用”、Key 来源、服务商、模型和错误信息。常见状态如下：

| 提示 | 含义 |
| --- | --- |
| `当前可用` | 服务商接受了请求并返回了有效响应外壳 |
| HTTP 400 | 模型 ID 或请求参数不被服务商接受 |
| HTTP 401/403 | Key 无效，或账户/模型没有访问权限 |
| HTTP 429 | 请求频率、额度、余额或账单限制 |
| `模型 JSON 缺少诊断结构` | 完整诊断输出不符合 Schema；连接测试不应出现此提示 |

连接测试不是确定性测试的一部分。真实模型不可用时，采集、检查、时间对齐、判定和报告仍可以使用 Mock 或独立完成。

切换四种模式时，页面会清空旧的连接提示和临时 API Key，但不会修改项目根目录的 `.env`。

## 4. 新建任务

“新建任务”用于创建合成型采集任务。测试工程师先填写任务名称，再选择数据模式、场景和参考时钟；
选择“自定义”后还可以填写视频和 IMU 参数。点击“保存采集任务”只会创建任务，不会立即执行。

### 4.1 创建任务时的通用选项

| 控件 | 选项或操作 | 作用 |
| --- | --- | --- |
| 任务名称 | 输入 80 字以内的名称 | 用于在任务列表和运行详情中识别任务；为空或与已有任务重名（不区分大小写）不能保存 |
| 数据模式 | 快速、标准、自定义 | 选择固定预设或展开详细配置 |
| 场景 | 正常采集、故障场景、固定偏移或线性漂移 | 决定生成数据中的现象和预期检查 |
| 参考时钟 | 相机 1～4、IMU | 指定时间对齐使用的参考通道 |
| 随机种子 | 默认固定；点击“刷新”生成新种子 | 决定合成故障位置和噪声序列，并在运行详情中记录 |
| 保存采集任务 | 按当前配置创建任务 | 只保存任务，不立即执行；名称为空或配置非法时不能保存 |

任务名称会在保存时做不区分大小写的重名检查，已归档任务也不能使用相同名称。

### 4.2 随机种子和参考时钟

随机种子不是展示用标签，而是合成数据生成器的输入。它决定故障位置和噪声序列；相同版本、配置和种子可以复现等价数据，运行详情会记录实际使用的种子。

快速和标准模式默认使用固定种子 `20260822`。需要生成一组不同的故障位置或噪声时，点击“刷新随机种子”后再保存任务，种子格式为 `HHMMSSmmm`。

重新执行同一任务不会自动换种子；需要新建任务，或在新建页面刷新种子后再保存。自定义模式还可以直接填写 `0～2147483647` 的整数种子。

参考时钟是跨通道时间对齐的基准，不会改写原始时间戳。普通采集只记录它；合成的固定偏移和线性漂移场景用它计算对齐结果，导入真实数据时只用于逻辑对齐和判断，不参与数据生成。

### 4.3 快速模式

快速模式是用于本地演示和快速回归的固定预设，视频和 IMU 参数不可单独修改；随机种子默认固定，也可以刷新：

| 参数 | 固定值 | 效果 |
| --- | --- | --- |
| 时长 | 2 秒 | 生成短媒体，适合快速验证 |
| 视频 | 2 路、640×360、30 FPS、MP4、H.264 | 文件小、生成快，覆盖双路视频 |
| 码率 | 3000 kbps、CBR | 目标码率稳定，便于检查视频编码契约 |
| IMU | CSV、100Hz、六轴 | 每秒约 100 个传感器样本，含三轴加速度和三轴角速度 |
| 随机种子 | 默认 `20260822`；可刷新 | 相同版本、配置和种子下可复现等价数据 |

快速模式的 IMU 是 100Hz，不是 50Hz。它适合演示双路视频的完整链路，但不能代表所有采样率边界。

### 4.4 标准模式

标准模式也是固定预设，视频和 IMU 参数不可单独修改；随机种子默认固定，也可以刷新：

| 参数 | 固定值 | 效果 |
| --- | --- | --- |
| 时长 | 5 秒 | 使用当前实现允许的最长实际媒体时长 |
| 视频 | 4 路、1280×720、30 FPS、MP4、H.264 | 覆盖多路视频和更高媒体负载 |
| 码率 | 6000 kbps、CBR | 便于在多路条件下复查视频码率 |
| IMU | CSV、200Hz、六轴 | 提供更高传感器采样密度 |
| 随机种子 | 默认 `20260822`；可刷新 | 用于重复性比较 |

### 4.5 自定义模式

自定义模式允许组合以下参数。提交前页面和后端都会校验边界：

| 参数 | 可选值或范围 | 主要影响 |
| --- | --- | --- |
| 时长 | 2～300 秒 | 影响任务时间线和虚拟长稳指标；实际媒体最多生成 5 秒 |
| 视频路数 | 1～4 路 | 影响媒体数量、文件规模和多路同步检查 |
| 分辨率 | 640×360、1280×720、1920×1080 | 分辨率越高，像素量、文件规模和生成成本越大 |
| 帧率 | 24、25、30、60、120 FPS | 影响每路视频帧数量和逐帧映射密度 |
| 容器 | MP4、MKV | 影响媒体封装格式；编码仍固定为 H.264 |
| 码率 | 100～50000 kbps，必须为 100 的整数倍 | 影响视频目标数据率和码率检查结果 |
| 码率模式 | CBR、VBR | CBR 约束目标码率；VBR 允许码率随内容变化 |
| IMU 格式 | CSV、JSONL | 只改变序列化格式，不改变六轴字段语义 |
| IMU 采样率 | 50、100、200、500Hz | 影响样本密度、间隔检查和逐帧最近邻误差 |
| 随机种子 | 默认固定；可刷新或填写 `0～2147483647` | 相同种子用于重复生成等价数据和故障 |
| 参考时钟 | camera_1～camera_4 或 IMU | 决定时间对齐使用的参考通道 |

路数、分辨率、帧率和实际媒体时长共同影响文件规模。超过安全像素帧数上限时，任务不会保存或运行。
300 秒任务不会生成 300 秒真实视频，而是以虚拟时间模拟温升、漂移和存储趋势，并在报告中标注来源。

### 4.6 IMU 采样率的选择

- **50Hz**：每 20ms 一个样本，适合验证低采样率边界；只允许在自定义模式使用。
- **100Hz**：每 10ms 一个样本，是快速模式、标准模式和实际导入的最低推荐密度。
- **200Hz**：每 5ms 一个样本，时间间隔更细，逐帧最近邻的理论误差通常更小。
- **500Hz**：每 2ms 一个样本，数据量和处理成本更高，适合高密度采样演示。

采样率越高不等于测试结论一定更好：它会改变文件大小、间隔分布和最近邻匹配机会；是否通过仍由确定性检查和阈值决定。

### 4.7 内置场景和预期检查

选择场景决定合成数据注入的故障真值。下拉框中的“固定偏移”和“线性漂移”用于生成时间不同步数据，供第 7 章的时间分析和对齐复核使用；
它们仍然是“新建任务”的场景选项，不是单独的页面。

| 场景 | 注入或模拟现象 | 预期重点检查 |
| --- | --- | --- |
| 正常采集 | 视频、六轴 IMU、状态和日志保持正常 | 不应误报视频、IMU、资源或存储故障 |
| 单路视频掉帧 | 按随机种子选择一路视频：`camera_(种子 % 路数 + 1)`；该路出现帧缺失或间隔异常 | 视频帧率、帧间隔、掉帧和异常窗口检查失败或命中；运行详情显示具体通道和异常时间窗 |
| IMU 异常 | 注入丢样、重复样本或时间戳倒退 | IMU 丢样、重复、倒退和间隔分布检查命中 |
| 存储不足 | 存储指标下降并导致录制提前停止 | 存储最低值、提前停止和日志关联检查命中 |
| 温升关联组合故障 | 温度上升后同时出现视频掉帧和 IMU 丢样 | 温度、视频、IMU 和日志的同窗口关联检查命中 |
| 固定偏移 | 让 `camera_2` 至最后一路视频及 IMU 相对 `camera_1` 产生稳定时间偏移 | 固定偏移估计、对齐参数和残差输出；运行详情显示目标通道 |
| 线性漂移 | 让 `camera_2` 至最后一路视频及 IMU 相对 `camera_1` 产生随时间增长的时间偏移 | 线性漂移估计、趋势和对齐后残差输出；运行详情显示目标通道 |

故障真值只存在于合成型数据。实际导入数据不得伪造 `fault_truth.json`，因此导入型运行不能计算命中、漏判或无证据推测的真值指标。

## 5. 根据导入生成：实际测试 ZIP

“根据导入生成”是独立页面，一次只选择一个 ZIP。推荐先下载 `manifest.json` 模板，准备好 ZIP 后再上传和校验。
上传、校验、转换和建任务请求进行时，相应按钮会禁用。

| 控件 | 操作 | 作用和限制 |
| --- | --- | --- |
| 实际测试 ZIP | 选择一个 `.zip` 文件 | 作为导入源；不接受多个文件或其他格式 |
| 权限确认 | 勾选“我确认具有处理和展示这些数据的权限” | 未确认时不能导入；确认责任由操作者承担 |
| 下载 manifest.json 模板 | 下载预填好的 JSON 示例 | 普通用户通常只需修改文件路径和通道名，模板中的技术字段可保留默认值 |
| 导入实际测试文件 | 先上传并建立隔离区记录 | 不代表校验通过，也不会直接创建任务 |
| 校验导入文件 | 对已上传记录执行安全、结构和兼容性校验 | 没有上传记录时不可用；上传完成后显示“文件已上传，尚未校验” |
| 转为标准格式 | 处理“非标准但可转换”的记录 | 仅在该状态下可用；当前版本通过弹窗说明暂不支持自动转换 |
| 导入任务名称 | 输入任务名称 | 创建任务时必填 |
| 测试标签 | 输入可选标签 | 便于后续识别和筛选 |
| 加入任务列表 | 将校验通过的导入记录创建为任务 | 必须校验通过、名称非空且当前没有其他导入操作 |

### 5.1 ZIP 基本限制

| 项目 | 限制 |
| --- | --- |
| ZIP 文件 | 最大 2GiB |
| 解压总大小 | 最大 10GiB |
| 文件数量 | 最多 100 个 |
| 单文件大小 | 最大 5GiB |
| 压缩比 | 不超过 100:1 |
| 禁止内容 | 路径穿越、符号链接、加密条目和 ZIP 炸弹风险 |

上传和解压写入 Git 忽略的项目数据目录隔离区。临时隔离区默认保留 24 小时并支持手工清理；校验通过后才原子移动到正式目录。

### 5.2 manifest 字段

manifest 是导入包的元数据入口，必须直接放在 ZIP 根目录，不能再套一层外部文件夹。一个最小示例：

```json
{
  "schema_version": "1.0",
  "time_source": "device_clock",
  "videos": [{"channel": "camera_1", "path": "videos/camera_1.mp4", "codec": "h264", "container": "mp4", "fps": 30, "resolution": "1280x720", "bitrate_kbps": 2500, "time_source": "container_pts", "start_raw_device_timestamp_ns": 0}],
  "imu": {"path": "imu.csv", "format": "csv", "sample_rate_hz": 100, "time_source": "device_clock"}
}
```

视频必须声明 1～4 路，每路使用 MP4/MKV 和 H.264；IMU 必须声明 CSV/JSONL 和采样率，实际采样率至少为 100Hz。
普通 IMU CSV 可使用 `time`、`timestamp_s`、`timestamp_ms`、`timestamp_us`、`timestamp_ns` 等时间列，系统会按字段名换算为秒。

IMU 的六轴列名优先使用 `accel_x`、`accel_y`、`accel_z`、`gyro_x`、`gyro_y`、`gyro_z`；带单位的内部名称
`accel_x_m_s2` 和 `gyro_x_rad_s` 仍然兼容。系统会保留原始文件，不会用对齐时间替换用户的原始时间字段。

### 5.3 导入状态和处理方式

1. **上传**：先确认具有处理和展示权限，再选择 ZIP 并点击“导入实际测试文件”。
2. **已上传**：上传成功后显示“文件已上传，尚未校验”；这一步只保存文件，不代表校验通过。
3. **校验**：点击“校验导入文件”，平台依次进行安全、结构和兼容性校验。
4. **通过**：填写任务名称和测试标签，点击“加入任务列表”；创建后不会自动运行。
5. **不通过**：显示错误，不能加入任务列表；如果是非标准但可转换的格式，则进入下一步。
6. **非标准但可转换**：可以点击“转为标准格式”；当前版本会弹窗说明暂不支持自动转换，不能把猜测结果当作标准数据。
7. **警告**：缺少可选设备状态或日志时允许加入，但警告会保留在任务和报告中。

## 6. 已保存任务

“已保存任务”是任务生命周期管理页面，用来查找已经创建的合成型任务和导入型任务，并根据任务是否执行过决定可以做什么。
它保存的是任务记录和任务配置的入口，不是运行结果列表；运行结果、检查证据和诊断历史应进入对应的运行详情查看。

### 6.1 列表和筛选

打开“已保存任务”后，平台从后端重新读取任务列表。每张任务卡显示任务名称、来源、执行状态和归档状态；列表按任务创建顺序倒序排列，
每页最多显示 10 条。页面显示当前页和任务总数，任务总数是当前筛选条件下的总数，不只是当前页的数量。

| 筛选项 | 选项 | 含义 |
| --- | --- | --- |
| 来源 | 全部来源、合成数据、导入实际数据 | 按任务创建方式筛选；合成数据来自“新建任务”，导入实际数据来自“根据导入生成” |
| 执行状态 | 全部执行状态、未执行、已有运行 | “未执行”表示任务没有任何运行记录；“已有运行”表示至少创建过一次运行 |
| 归档状态 | 全部归档状态、未归档、已归档 | 按任务当前是否归档筛选；归档不会删除任务或运行证据 |

选择任意筛选项后，页面会立即从第 1 页重新加载结果。筛选条件可以组合使用，例如只查看“导入实际数据、已有运行、未归档”的任务。
筛选没有匹配结果时，任务总数为 0；这表示当前条件下没有任务，不表示任务数据丢失。

### 6.2 任务卡和生命周期状态

任务卡现在集中展示任务管理所需的信息，包括来源、模式、场景、执行状态、归档状态、运行次数和创建时间；视频、IMU 的完整参数仍需打开任务或对应的运行详情核对。
不要根据任务卡上的来源和状态推断自动化检查是否通过。

| 状态组合 | 页面显示 | 可执行操作 | 说明 |
| --- | --- | --- | --- |
| 未执行、未归档 | 未执行 · 未归档 | 删除 | 任务尚未产生运行证据，可以删除任务记录 |
| 已有运行、未归档 | 已有运行 · 未归档 | 归档 | 不能删除；归档后保留任务、运行、报告和诊断 |
| 已有运行、已归档 | 已有运行 · 已归档 | 无删除操作 | 作为历史记录保留，不能通过级联删除清理运行证据 |
| 未执行、已归档 | 未执行 · 已归档 | 删除 | 只要没有运行记录仍可删除；归档状态不会改变删除资格 |

“已有运行”只根据运行记录数量判断，与最近一次运行是通过、失败、取消还是中断无关。归档也不会改变任何运行的状态，
不会修改原始导入文件、合成配置、自动化检查、人工结果或 AI 诊断。

### 6.3 删除任务

只有从未执行的任务可以删除。点击任务卡中的“删除任务 <任务名称>”后，后端会再次检查任务是否存在运行记录；如果在页面加载后任务已经被其他操作执行，
删除会被拒绝，并提示“已有运行记录的任务只能归档，不能删除”。这种拒绝是保护证据的正常行为，不要通过刷新或重复点击绕过。

删除成功后，任务记录不再出现在列表中，也不能通过任务详情 API 找回；因此删除前应确认任务名称和执行状态，误删时只能重新创建任务。
删除未执行任务不会影响其他任务、导入记录或已有运行。

### 6.4 归档任务

已有运行记录的任务只能归档。点击“归档任务 <任务名称>”后，平台把任务标记为已归档，并重新返回该任务的生命周期读模型。
归档是可追溯性操作，不是删除操作：运行详情、媒体产物、检查结果、人工复核、诊断和报告仍然保留。

归档后可以使用“归档状态 → 已归档”筛选历史任务；需要查看当前仍可管理的任务时，选择“未归档”。当前页面没有提供取消归档按钮，
不要把“已归档”改写成“已删除”。

### 6.5 刷新、分页和异常处理

| 操作或现象 | 正确处理 | 不会发生什么 |
| --- | --- | --- |
| 刷新已保存任务 | 重新读取当前列表；未传入新条件时保留当前筛选和页码 | 不会执行任务、重跑运行或修改任务配置 |
| 修改筛选 | 从第 1 页读取组合筛选结果 | 不会删除筛选结果之外的任务 |
| 上一页/下一页 | 在有对应页面时切换并重新读取 | 不会改变任务的生命周期状态 |
| 列表加载失败 | 查看页面错误提示，确认后端健康后再刷新 | 不应把暂时无法加载当成空列表 |
| 删除返回 409 | 转为归档操作，并确认运行详情仍可打开 | 不会删除运行证据 |
| 归档返回失败 | 保留当前页面状态并检查后端日志或网络 | 不会假设归档已经成功 |

列表接口使用 `GET /api/collection-tasks/saved`，默认按第 1 页、每页 10 条读取；删除使用
`DELETE /api/collection-tasks/{task_id}`，成功返回 `204 No Content`；归档使用
`POST /api/collection-tasks/{task_id}/archive`，成功返回更新后的任务生命周期读模型。页面不会把完整任务配置或运行明细塞进列表响应。
任务被创建、执行或归档后，应点击“刷新已保存任务”确认列表中的状态已更新，再继续下一步复核。

### 6.6 推荐使用流程

1. 创建合成任务，或在导入校验通过后加入任务列表。
2. 打开“已保存任务”，先按来源和归档状态缩小范围，再查看执行状态。
3. 对未执行且不再需要的任务执行删除；需要测试的任务从任务入口启动运行。
4. 对已经产生运行记录但不再作为当前任务使用的任务执行归档。
5. 归档后通过“已归档”筛选确认任务仍可追溯，并从运行详情导出报告或证据包。

已保存任务列表不替代运行详情，也不替代报告验收。任务卡显示“已有运行”只说明运行记录存在，正式结论仍以确定性检查、时间分析、人工复核和必要的诊断证据为准。

## 7. 运行逻辑、任务生命周期和时间分析

### 7.1 运行逻辑和生命周期

合成型任务保存时不配置“判定模式”，也不会默认生成正式规格依据。运行时平台自动执行适用的确定性检查；缺少可选证据的检查标记为未执行。

导入型任务只使用实际测试 ZIP 中已有的证据进行检查，不生成合成故障真值。运行前应确认参考时钟，平台不会把导入数据伪装成有正式规格依据的验收任务。

从未执行的合成型或导入型任务可以删除。已有运行记录的任务只能归档，不能删除，也不能级联删除运行记录、原始输入、报告或诊断。

在运行详情录入人工检查结果时，检查项名称应描述人工要确认的事项，例如“外壳是否有裂纹”，不要填写文件名或自动检查器名称。
人工状态包括通过、失败、阻塞和未执行，与自动化检测结果独立保存。CSV/Excel 应使用兼容模板；面向 Excel 的 CSV 使用 UTF-8 BOM。

人工结果 CSV 模板列顺序固定为：

```csv
name,status,actual_result,notes,executed_at
外壳是否有裂纹,not_run,,待现场检查,
```

其中 `status` 只能使用 `passed`、`failed`、`blocked` 或 `not_run`。该模板与证据 ZIP 中的
`manual-check-results.csv` 使用同一契约，可直接通过运行详情的人工结果导入入口回导。

运行详情中的人工结果控件包括：检查项名称、状态、实际结果、执行时间、附件和备注；“保存人工结果”用于新增，
编辑已有项目时按钮显示“更新人工结果”，“导入 CSV 或 Excel”用于批量导入。人工结果只补充人工复核，不改变自动化检查、判定或原始证据。

### 7.2 时间分析和逐帧映射

平台同时保留三类时间：

1. **原始设备时间**：设备时钟中的原始值，例如 `raw_device_timestamp_ns`。
2. **相对时间**：从采集起点计算的运行时间，便于比较同一运行内的间隔。
3. **对齐时间**：根据参考时钟和对齐方法计算的派生结果，不回写原始视频或 IMU 文件。

导入 IMU 时，平台优先识别 `time`、`timestamp_s`、`timestamp_ms`、`timestamp_us`、`timestamp_ns`、`relative_time`、
`elapsed_time` 和 `device_time` 等字段。带有 `ms`、`us` 或 `ns` 后缀的值会分别换算为秒；没有单位后缀时按秒处理。

固定偏移适用于通道间时差基本稳定的场景；线性漂移适用于偏移随时间近似线性变化的场景。两种方法都会输出参考时钟、
锚点、参数、对齐前指标、对齐后残差和内容同步结果。时间接近不等于画面内容同步，二者分开评价。

逐帧映射对每一路视频的每一帧执行：平台使用视频帧时间，在完成时钟变换的 IMU 时间序列中选择差值最小的样本。
独立映射文件至少包含视频通道、帧号、视频原始/相对/对齐时间、IMU 样本序号、IMU 原始/相对/对齐时间、
真实时间差、容差和匹配状态。没有完全相同采样时刻时，报告应保留真实时间差，不能宣称完全同时。

### 7.3 运行详情中的检查结果

运行完成后，运行详情展示随机种子、故障注入目标、自动化检查和时间分析。故障场景会列出实际目标通道；掉帧场景还会列出异常时间窗。

新建任务不提供“需求验收、工程目标、摸底分析”选择，也不从不存在的正式规格、工程目标或版本基线推导结论。历史任务或显式接口带有判定配置时，才会额外显示对应的判定结果。

运行流程中的主要操作如下：

| 控件或区域 | 操作 | 作用和限制 |
| --- | --- | --- |
| 执行任务 | 从已保存任务启动 | 创建一次运行并按阶段执行；已有运行的任务仍可再次执行 |
| 取消运行 | 运行未结束时点击 | 停止后续阶段，但不删除已经生成的产物和记录 |
| 重新执行 | 运行结束后点击 | 用同一任务配置创建新运行，不覆盖原运行 |
| 自动化检测结果 | 查看每项检查 | 显示通过/失败、指标、异常窗口和证据引用；合成任务可显示故障真值对照 |
| 注入说明 | 查看场景目标 | 显示掉帧、固定偏移或线性漂移实际作用的通道和时间范围 |
| 判定结果 | 按需查看 | 仅对历史任务或显式提供判定配置的运行显示，不等同于 AI 意见 |

## 8. 人工结果与复核

本章专门说明测试工程师在运行详情中进行人工复核的操作。人工结果与自动化检查独立保存，不能用人工结果改写自动化结果或故障真值。

| 控件 | 填写或操作方式 | 作用 |
| --- | --- | --- |
| 检查项名称 | 填写要由人员确认的事项，例如“外壳是否有裂纹” | 说明人工检查对象；不要填写文件名或检查器名称 |
| 状态 | 通过、失败、阻塞、未执行 | 表示人工检查结论；未执行表示没有完成检查 |
| 实际结果 | 填写现场观察或测量结果 | 保存可读的人工证据摘要 |
| 执行时间 | 填写人工检查发生的时间 | 记录复核时间，便于追溯 |
| 附件 | 选择小型人工复核附件 | 保存安全元数据；附件仍受大小和类型限制 |
| 备注 | 填写补充说明 | 记录异常背景、限制和后续动作 |
| 保存人工结果 | 新增一条人工结果 | 校验通过后保存，不影响自动化结果 |
| 更新人工结果 | 修改已存在的人工结果 | 保存修改后的人工复核内容 |
| 导入 CSV 或 Excel | 按模板批量导入 | 批量新增或更新人工结果；错误行会返回具体原因 |

CSV 必须使用 `name,status,actual_result,notes,executed_at` 列顺序，`status` 只能是 `passed`、`failed`、`blocked` 或 `not_run`。
人工结果保存或诊断状态变化后，重新导出报告和证据包，确保交付物反映最新状态。

## 9. 报告和证据导出

运行详情提供独立 HTML 报告、原始视频单独下载和证据 ZIP 下载。证据 ZIP 默认排除原始视频，只有显式选择时才包含受限小样。

ZIP 按下载时的当前状态生成，通常包含报告、结构化检查、人工结果、日志、缩略图、文件清单、哈希和逐帧视频—IMU 映射。
人工结果或诊断更新后，应重新导出。下载失败时不能留下可被误认为完整的半成品 ZIP。

| 操作 | 作用 | 使用时机 |
| --- | --- | --- |
| 打开独立 HTML 报告 | 在新标签页查看当前运行报告 | 需要浏览器阅读、打印或分享报告时 |
| 下载 ZIP 证据包 | 下载不含原始视频的完整证据包 | 常规归档和提交评审 |
| 下载含视频小样的 ZIP 证据包 | 在证据包中加入受限视频小样 | 需要复核画面时；包体和敏感数据更多 |
| 下载原始视频 | 单独下载某一路原始视频 | 需要离线复核原始画面时 |

下载链接按当前状态生成；人工结果或诊断变化后应重新下载，不能继续使用旧包作为最新结论。

## 10. 推荐复现路径和排错

首次演示建议：快速正常采集 → 快速掉帧场景 → 查看确定性检查和时间映射 → Mock 诊断 → 下载 HTML 和默认证据 ZIP。
需要演示真实数据链路时，再准备符合本手册 manifest 契约的本地 ZIP。

完整自动化验收命令见 README 的“一键 Mock 验收”和“验证命令”章节。验收产物写入 Git 忽略的 `tmp` 目录，不要提交这些本地数据。

如果页面显示“服务暂不可用”，先检查后端健康地址；如果导入不能加入任务列表，先查看安全错误、结构错误和兼容性错误的分类；
如果 AI 失败，先使用 Mock 完成测试，再单独检查服务商、模型、Key 和端点。

| 排错操作 | 作用 | 不会做什么 |
| --- | --- | --- |
| 刷新仪表盘 | 重新读取运行统计和近期失败 | 不会重新运行任务或生成诊断 |
| 刷新已保存任务 | 重新读取任务列表和筛选结果 | 不会修改任务配置 |
| 重新执行 | 创建同配置的新运行 | 不会覆盖旧运行 |
| 生成 Mock/真实模型诊断 | 为已完成运行创建一次诊断运行 | 不会改变自动化检查和判定结果 |
| 刷新诊断状态 | 重新读取诊断历史 | 不会重新提交模型请求 |
| 应用锚点复核 | 保存选中的锚点和复核时间并重新计算对齐 | 不会修改原始检测时间和原始媒体 |
| 保存/更新人工结果 | 保存人工检查项及附件元数据 | 不会覆盖自动化检查结果 |

如果页面操作无效，先确认按钮是否因运行状态、缺少文件、未勾选权限确认或字段校验而禁用，再查看页面错误提示和后端日志。
