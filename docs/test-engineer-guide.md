# 测试工程师使用手册

本文面向本地运行平台的测试工程师，说明每个配置项会产生什么效果、如何选择场景、如何导入实际数据，
以及如何判断、复核和导出一次运行。平台只使用虚构设备、公开格式和合成数据；不要把公司数据或未获授权的实际数据放入仓库。

## 1. 启动平台

先按 README 的“环境准备”安装依赖，再分别启动后端和前端：

```powershell
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --reload --env-file .env
pnpm --dir frontend dev
```

浏览器打开 `http://127.0.0.1:5173`。默认使用 Mock 模式，不需要真实 API Key。

## 2. 页面和基本工作流

平台的页面或标签含义如下：

| 页面 | 用途 |
| --- | --- |
| 仪表盘 | 查看运行统计、近期失败和诊断状态，并进入运行详情 |
| 新建任务 | 创建合成型采集任务 |
| 根据导入生成 | 上传、校验实际测试 ZIP，并创建导入型采集任务 |
| 已保存任务 | 按来源、运行状态和归档状态筛选任务，每页最多 10 条 |
| 运行详情 | 查看阶段、产物、检查、对齐、人工结果、诊断和导出 |
| 设置 | 选择 AI 服务商、模型并进行连接测试 |

推荐流程是：创建或导入任务 → 检查配置 → 手工启动运行 → 查看确定性检查 → 查看时间分析 → 录入人工结果 →
按需运行 AI 诊断 → 导出报告和证据。

## 3. 合成任务：模式、参数和效果

### 3.1 快速模式

快速模式是用于本地演示和快速回归的固定预设，参数不可单独修改：

| 参数 | 固定值 | 效果 |
| --- | --- | --- |
| 时长 | 2 秒 | 生成短媒体，适合快速验证 |
| 视频 | 1 路、640×360、15 FPS、MP4、H.264 | 文件小、生成快，只覆盖单路视频 |
| 码率 | 2500 kbps、CBR | 目标码率稳定，便于检查视频编码契约 |
| IMU | CSV、100Hz、六轴 | 每秒约 100 个传感器样本，含三轴加速度和三轴角速度 |
| 随机种子 | 20260822 | 相同版本和配置下可复现等价数据 |

快速模式的 IMU 是 100Hz，不是 50Hz。它适合演示完整链路，但不能代表所有采样率边界。

### 3.2 标准模式

标准模式也是固定预设：

| 参数 | 固定值 | 效果 |
| --- | --- | --- |
| 时长 | 5 秒 | 使用当前实现允许的最长实际媒体时长 |
| 视频 | 4 路、1280×720、30 FPS、MP4、H.264 | 覆盖多路视频和更高媒体负载 |
| 码率 | 2500 kbps、CBR | 便于在多路条件下复查视频码率 |
| IMU | CSV、100Hz、六轴 | 与快速模式保持同一传感器采样密度 |
| 随机种子 | 20260822 | 用于重复性比较 |

### 3.3 自定义模式

自定义模式允许组合以下参数。提交前页面和后端都会校验边界：

| 参数 | 可选值或范围 | 主要影响 |
| --- | --- | --- |
| 时长 | 2～300 秒 | 影响任务时间线和虚拟长稳指标；实际媒体最多生成 5 秒 |
| 视频路数 | 1～4 路 | 影响媒体数量、文件规模和多路同步检查 |
| 分辨率 | 640×360、1280×720、1920×1080 | 分辨率越高，像素量、文件规模和生成成本越大 |
| 帧率 | 15、24、25、30、60 FPS | 影响每路视频帧数量和逐帧映射密度 |
| 容器 | MP4、MKV | 影响媒体封装格式；编码仍固定为 H.264 |
| 码率 | 256～50000 kbps | 影响视频目标数据率和码率检查结果 |
| 码率模式 | CBR、VBR | CBR 约束目标码率；VBR 允许码率随内容变化 |
| IMU 格式 | CSV、JSONL | 只改变序列化格式，不改变六轴字段语义 |
| IMU 采样率 | 50、100、200、500Hz | 影响样本密度、间隔检查和逐帧最近邻误差 |
| 随机种子 | 0～2147483647 | 相同种子用于重复生成等价数据和故障 |
| 参考时钟 | camera_1～camera_4 或 IMU | 决定时间对齐使用的参考通道 |

路数、分辨率、帧率和实际媒体时长共同影响文件规模。超过安全像素帧数上限时，任务不会保存或运行。
300 秒任务不会生成 300 秒真实视频，而是以虚拟时间模拟温升、漂移和存储趋势，并在报告中标注来源。

### 3.4 IMU 采样率的选择

- **50Hz**：每 20ms 一个样本，适合验证低采样率边界；只允许在自定义模式使用。
- **100Hz**：每 10ms 一个样本，是快速模式、标准模式和实际导入的最低推荐密度。
- **200Hz**：每 5ms 一个样本，时间间隔更细，逐帧最近邻的理论误差通常更小。
- **500Hz**：每 2ms 一个样本，数据量和处理成本更高，适合高密度采样演示。

采样率越高不等于测试结论一定更好：它会改变文件大小、间隔分布和最近邻匹配机会；是否通过仍由确定性检查和阈值决定。

## 4. 内置场景和预期检查

选择场景决定合成数据注入的故障真值。固定偏移和线性漂移是时间分析场景，不是普通设备故障场景。

| 场景 | 注入或模拟现象 | 预期重点检查 |
| --- | --- | --- |
| 正常采集 | 视频、六轴 IMU、状态和日志保持正常 | 不应误报视频、IMU、资源或存储故障 |
| 单路视频掉帧 | 指定视频通道出现帧缺失或间隔异常 | 视频帧率、帧间隔、掉帧和异常窗口检查失败或命中 |
| IMU 异常 | 注入丢样、重复样本或时间戳倒退 | IMU 丢样、重复、倒退和间隔分布检查命中 |
| 存储不足 | 存储指标下降并导致录制提前停止 | 存储最低值、提前停止和日志关联检查命中 |
| 温升关联组合故障 | 温度上升后同时出现视频掉帧和 IMU 丢样 | 温度、视频、IMU 和日志的同窗口关联检查命中 |
| 固定偏移 | 通道间存在稳定的时间偏移 | 固定偏移估计、对齐参数和残差输出 |
| 线性漂移 | 多个共同事件之间存在时钟速率差异 | 线性漂移估计、趋势和对齐后残差输出 |

故障真值只存在于合成型数据。实际导入数据不得伪造 `fault_truth.json`，因此导入型运行不能计算命中、漏判或无证据推测的真值指标。

## 5. 时间分析和逐帧映射

平台同时保留三类时间：

1. **原始设备时间**：设备时钟中的原始值，例如 `raw_device_timestamp_ns`。
2. **相对时间**：从采集起点计算的运行时间，便于比较同一运行内的间隔。
3. **对齐时间**：根据参考时钟和对齐方法计算的派生结果，不回写原始视频或 IMU 文件。

固定偏移适用于通道间时差基本稳定的场景；线性漂移适用于偏移随时间近似线性变化的场景。两种方法都会输出参考时钟、
锚点、参数、对齐前指标、对齐后残差和内容同步结果。时间接近不等于画面内容同步，二者分开评价。

逐帧映射对每一路视频的每一帧执行：平台使用视频帧时间，在完成时钟变换的 IMU 时间序列中选择差值最小的样本。
独立映射文件至少包含视频通道、帧号、视频原始/相对/对齐时间、IMU 样本序号、IMU 原始/相对/对齐时间、
真实时间差、容差和匹配状态。没有完全相同采样时刻时，报告应保留真实时间差，不能宣称完全同时。

## 6. 三种判定模式

判定模式决定报告能否给出产品意义上的结论：

| 模式 | 阈值来源 | 可以输出什么 | 不能输出什么 |
| --- | --- | --- | --- |
| 需求验收 | 正式规格 | 合格或不合格 | 不得让 AI 补充阈值 |
| 工程目标 | 工程目标 | 当前 POC/EVT 目标下的评价 | 不得表述为产品承诺 |
| 摸底分析 | 版本基线 | 分布、趋势和版本对比 | 不输出合格或不合格 |

`max_failed_checks` 表示允许失败的确定性检查数量；超过阈值时会影响判定。`max_alignment_residual_ms` 可用于约束对齐残差。
非摸底模式必须提供阈值，阈值不能为负数且必须与阈值来源匹配。AI 不能生成、修改或解释成新的正式阈值。

## 7. 导入实际测试 ZIP

“根据导入生成”是独立页面，一次只选择一个 ZIP。上传、校验、转换和建任务请求进行时，相应按钮会禁用。

### 7.1 ZIP 基本限制

| 项目 | 限制 |
| --- | --- |
| ZIP 文件 | 最大 2GiB |
| 解压总大小 | 最大 10GiB |
| 文件数量 | 最多 100 个 |
| 单文件大小 | 最大 5GiB |
| 压缩比 | 不超过 100:1 |
| 禁止内容 | 路径穿越、符号链接、加密条目和 ZIP 炸弹风险 |

上传和解压写入 Git 忽略的项目数据目录隔离区。临时隔离区默认保留 24 小时并支持手工清理；校验通过后才原子移动到正式目录。

### 7.2 manifest 字段

manifest 是导入包的元数据入口。一个最小示例：

```json
{
  "schema_version": "1.0",
  "videos": [
    {
      "channel": "camera_1",
      "path": "videos/camera_1.mp4",
      "codec": "h264",
      "container": "mp4",
      "fps": 30,
      "resolution": "1280x720",
      "bitrate_kbps": 2500,
      "time_source": "container_pts_plus_device_start",
      "start_raw_device_timestamp_ns": 1000000000
    }
  ],
  "imu": {
    "path": "imu.csv",
    "format": "csv",
    "sample_rate_hz": 100
  }
}
```

字段含义：

| 字段 | 含义和校验要求 |
| --- | --- |
| `schema_version` | manifest 契约版本；不是 `1.0` 时标记为非标准但可转换 |
| `videos` | 视频数组，必须声明 1～4 路，每路独立描述 |
| `channel` | 视频通道名，例如 `camera_1`，用于逐帧映射和报告 |
| `path` | ZIP 内相对路径，必须指向 MP4 或 MKV 文件 |
| `codec` | 必须为 `h264` |
| `container` | 视频容器，必须为 `mp4` 或 `mkv` |
| `fps` | 视频帧率，必须使用平台支持的值 |
| `resolution` | 视频分辨率，必须使用平台支持的值 |
| `bitrate_kbps` | 视频码率，单位 kbps |
| `time_source` | 帧时间来源，必须说明如何从 PTS 和设备起始时间得到时间 |
| `start_raw_device_timestamp_ns` | 该路视频起始原始设备时间，不能用对齐时间替代 |
| `imu.path` | ZIP 内 IMU 文件的相对路径 |
| `imu.format` | `csv` 或 `jsonl` |
| `imu.sample_rate_hz` | 声明采样率，实际数据仍需通过至少 100Hz 校验 |

IMU 数据必须包含 `raw_device_timestamp_ns`、`relative_timestamp_s`、`accel_x_m_s2`、`accel_y_m_s2`、
`accel_z_m_s2`、`gyro_x_rad_s`、`gyro_y_rad_s` 和 `gyro_z_rad_s`。`aligned_timestamp_ns` 如果出现，只能是平台派生字段，
不能替换任何原始时间字段。设备状态、设备日志和其他附件可选，不能上传或伪造 `fault_truth.json`。

### 7.3 导入状态和处理方式

1. **上传**：确认具有处理和展示权限后上传 ZIP；相同 SHA-256 的 ZIP 不允许重复加入。
2. **校验**：先做安全/结构校验，再做平台兼容性校验。
3. **通过**：可以加入任务列表；加入后创建导入型任务，但不会自动运行。
4. **不通过**：显示错误，不能转换、不能加入任务列表，不能生成正式导入数据。
5. **非标准但可转换**：显示转换入口；首版转换功能只提示“开发中”。
6. **警告**：缺少可选设备状态或日志等非核心证据时允许加入，警告必须持续显示在任务和报告中。

文件名相同但 SHA-256 不同的数据包是不同导入。长期只保留哈希、首次导入时间、校验器版本、最终状态、错误/警告摘要和文件清单哈希。

## 8. 运行、人工结果和任务生命周期

导入型任务必须由测试工程师先配置参考时钟、判定模式和阈值，再手工启动。平台自动执行所有适用的确定性检查；缺少可选证据的检查标记为未执行。

从未执行的合成型或导入型任务可以删除。已有运行记录的任务只能归档，不能删除，也不能级联删除运行记录、原始输入、报告或诊断。

在运行详情录入人工检查结果时，检查项名称应描述人工要确认的事项，例如“外壳是否有裂纹”，不要填写文件名或自动检查器名称。
人工状态包括通过、失败、阻塞和未执行，与自动化检测结果独立保存。CSV/Excel 应使用兼容模板；面向 Excel 的 CSV 使用 UTF-8 BOM。

## 9. AI 诊断和安全边界

设置中可选择硅基流动、DeepSeek 或 Kimi。每个服务商的 Key、端点和模型目录相互隔离；不支持的模型不会静默回退。
连接测试和诊断请求显示服务商、模型、进行中、成功、失败或可重试状态。

AI 诊断是独立的诊断运行，不阻断数据生成、确定性检查、时间对齐、判定或原始报告。超时、限流和临时服务错误最多自动重试两次，
其他错误保留并允许手工重试。AI 不能生成阈值、控制设备、修改确定性结果、修改人工结果或覆盖原始证据。

## 10. 报告和证据导出

运行详情提供独立 HTML 报告、原始视频单独下载和证据 ZIP 下载。证据 ZIP 默认排除原始视频，只有显式选择时才包含受限小样。

ZIP 按下载时的当前状态生成，通常包含报告、结构化检查、人工结果、日志、缩略图、文件清单、哈希和逐帧视频—IMU 映射。
人工结果或诊断更新后，应重新导出。下载失败时不能留下可被误认为完整的半成品 ZIP。

## 11. 推荐复现路径和排错

首次演示建议：快速正常采集 → 快速掉帧场景 → 查看确定性检查和时间映射 → Mock 诊断 → 下载 HTML 和默认证据 ZIP。
需要演示真实数据链路时，再准备符合本手册 manifest 契约的本地 ZIP。

完整自动化验收命令见 README 的“一键 Mock 验收”和“验证命令”章节。验收产物写入 Git 忽略的 `tmp` 目录，不要提交这些本地数据。

如果页面显示“服务暂不可用”，先检查后端健康地址；如果导入不能加入任务列表，先查看安全错误、结构错误和兼容性错误的分类；
如果 AI 失败，先使用 Mock 完成测试，再单独检查服务商、模型、Key 和端点。
