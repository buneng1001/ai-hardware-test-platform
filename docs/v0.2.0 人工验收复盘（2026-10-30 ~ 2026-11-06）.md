# v0.2.0 人工验收复盘（2026-10-30 ~ 2026-11-06）

这份文档回答三件事：

1. 这轮验收实际改了什么；
2. 反复返工的根因是什么；
3. 下一次更新、下一个项目怎么避免同样的错误。

---

## 一、这轮验收改了什么（按主题）

### 1. 需求与用例导入

- 需求页支持填写需求说明、勾选「使用 AI 大模型解析上传文件」；
- 用例表模板增加「默认模板 / 上传模板」切换，默认模板 12 列；
- 软件版本来源改为二选一：保留导入版本 / 使用当前产品版本；
- 导入支持多行合并单元格（续行前向填充）；
- 修复 WPS 生成的 xlsx 因工作表范围写成 `A1` 导致「导入文件不包含数据行」。

### 2. 人工 / 自动化的语义

- 明确规则：**导入的原始用例永远是人工**；「生成自动化」是新建自动化副本，不覆盖原用例；
- 测试用例表类型列显示「人工」，附注「已生成自动化 / 自动化待校验」；
- 从测试用例表加入测试组一律按人工加入；自动化用例表加入按自动化加入；
- 同一条用例可以同时以「人工行 + 自动化行」存在于测试组，两行相邻排列。

### 3. 测试组

- 详情页重做为「一张表」：选择 / 序号 / 用例编号 / 标题 / 类型 / 测试类型 / 软件版本 / 数据包 / 移出；
- 顶部操作：执行自动化测试、隐藏、删除、返回；
- 数据包在表格内逐行选择，上方支持批量分配；
- 每页 20 条；
- 删除测试组、移出用例都改为居中弹窗确认；
- 加入测试组改为原地弹窗（选已有组或新建），不再跳页；
- 修复「同一条用例重复加入同一测试组」——后端靠联合主键 + `INSERT OR IGNORE` 幂等，并补了回归测试。

### 4. 人工测试结果

- 人工结果保存语义改为**不可变批次**：每次保存新建批次，旧批次保留可回看；
- 已保存批次不再被覆盖；
- 人工记录卡片只显示批次号 + 通过/不通过/阻塞/未执行计数，不再逐条列表；
- 人工用例过滤去掉 `test_type IN (manual, mixed)` 的硬编码，改为一律视为人工（只排除显式 automation）。

### 5. 自动化执行与报告

- 测试组顶部「执行自动化测试」一键预检 + 执行，执行中禁用、可取消，状态文字常驻；
- 报告分析跟随 AI 配置（不再是默认 `disabled`）；
- 报告结构改为：基本信息 → 产品形态 → 总通过率 → 模块汇总 → 未通过清单 → 阻塞/未执行 → 执行方式通过率 → 模块明细 → AI 分析 → 附录；
- 通过率口径：**通过 / 已测**，人工和自动化分列在后面；
- 报告与历史记录只列最终报告，每页 8 条；
- 报告预览与下载的 HTML 都加了右上角**可折叠目录**；
- 附件只列文件名，不嵌入内容。

### 6. AI

- 自动化判定提示词升级到 v3：四道硬门槛（可断言、数据可得、不主观、不依赖物理动作）+ 判定依据字段；
- 生成前选择范围：只生成未生成过的 / 全部重新判定 / 只处理勾选；
- 预期结果缺阈值的警告提前到生成阶段，并给出「去自动化用例表补充阈值」入口；
- 移除候选行上的「低可信度 · …」内部说明。

### 7. 基础设施

- 前端代理目标改为环境变量 `VITE_API_PROXY_TARGET`，默认 8020；
- Vite 固定绑定 `127.0.0.1`，修复 Windows 只监听 IPv6 导致 `127.0.0.1` 打不开；
- 一键启动脚本 `scripts/dev.ps1`：自动挑空闲端口、写代理、设置数据目录；
- 数据目录问题明确：验收数据在 `data/acceptance`，默认 `data` 是空库；
- 删除操作统一 `V020ConfirmDialog`（居中遮罩弹窗），去掉浏览器原生 `confirm` 和页面底部卡片；
- 所有表格分页统一 20 条（测试组详情的用例表、人工结果、报告历史 8 条）。

### 8. 本版本只做 UI 的部分（不接后端）

- 执行器管理弹窗：GitHub CI / Jenkins / 本地框架三种模式 + 模拟「测试连接」；
- 测试组内选择执行器、按执行器筛选；
- 执行流程演示：生成可执行用例（JSON）→ 校验/人工审核 → 触发执行器 → 回收结果；
- 数据存浏览器本地存储，不请求后端。

改动的分支：`codex/v0.2.0-manual-acceptance-2026-10-30`。

## 二、反复返工的根因

这轮验收最大的问题不是代码写错，而是**语义没对齐就开始实现**。

| 现象 | 根因 |
| --- | --- |
| 测试用例表显示「自动化」，加入测试组后全变人工 | 「类型」在展示和入库两处用了不同定义，没有先写出完整链路 |
| 列表页和详情页的执行弹窗不一样 | 新功能只在列表页实现，详情页保留旧入口，没有统一组件 |
| 删除确认出现在页面底部 | 用了页面内嵌确认块，而不是统一的模态弹窗 |
| 按钮文字被背景色盖住、单选框换行、按钮右对齐 | 全局 CSS 优先级冲突，没有在真实页面验收就交付 |
| 任务建好了却「看不到数据包」 | 把「任务」「数据包」「执行」三个概念当成一件事讲 |
| 报告一直显示「AI 未使用」 | 功能默认关闭，且界面读的是快照里的静态字段 |
| 导入 xlsx 报「不包含数据行」 | 用 `read_only` 读取，信任了文件里写坏的范围元数据 |
| 生成 JSON 时才提示阈值缺失 | 校验时机放得太晚，应该在生成用例时提示 |
| 默认端口 8000 反复被占 | 没有把端口做成配置，也没有提供多项目启动方式 |
| 「低可信度 · …」这类内部说明出现在界面 | 没区分「用户需要的信息」和「实现细节」 |

共同点：**先写代码，再让用户从界面上发现问题**。每一步都是真实反馈驱动，但代价是 40+ 次往返。

## 三、下次怎么避免（可执行规则）

### 写代码前（需求阶段）

1. **先写数据链路，再写界面**：一个字段（如「类型」「状态」）必须同时写清 数据来源 → 展示 → 可执行动作 三处，任何一处不一致就不动手。
2. **一个功能只允许一个入口**：新增入口前先搜现有入口，能复用组件就复用；不能复用时先说明为什么。
3. **默认值必须用户确认**：端口、分页大小、开关默认状态、保存语义（覆盖还是新增），这四类不许自己拍板。
4. **大改先出方案，方案里带界面草图**：这次多次返工都发生在「我以为你知道」。方案确认后再写代码。
5. **先定义名词**：任务、数据包、执行、测试组、执行器，每个词写一句定义，避免同名不同义。

### 写代码时

6. **危险操作统一模态**：删除、覆盖、清空、发布，一律 `V020ConfirmDialog`；禁止 `window.confirm` 和页面内嵌确认。
7. **所有表格默认 20 条分页**，新增表格时同步加分页和测试。
8. **文案分层**：给用户看的说明只写"要做什么"，不写"系统怎么实现"；内部判定信息（置信度、命中规则）不进界面。
9. **弹窗内表单不要沿用页面表单样式**：`label` 的 grid 布局会和单选框/勾选框打架，用独立类名。
10. **主题色按钮必须有对比度检查**：选中态、禁用态、hover 态三种都要看文字是否可见。
11. **外部文件解析不要信任元数据**：`read_only` 只在确认文件规范时使用；解析后过滤空行，并加坏文件回归测试。
12. **AI 能力跟随统一配置**：一个全局开关决定所有 AI 功能，界面显示当前模式（真实/模拟/关闭）。

### 验收时

13. **每次改完自己先截图看**：不要只跑测试就交付；布局、对齐、颜色必须眼见为实。
14. **列操作清单逐条走**：每个改动写 3~5 步操作（从哪个页面进、点什么、看什么），走完打勾。
15. **语义类改动必须回归旧数据**：改类型判定、保存语义时，用已有数据验证，而不是只建新数据。
16. **测试失败先看是不是自己改坏的**：这轮出现过多次并行跑测试偶发失败，单跑即过；区分"偶发"和"真失败"要花时间，但值得。

## 四、下一页开工前的检查清单（可直接抄）

- [ ] 这个功能有几个入口？能否只留一个？
- [ ] 涉及的字段在「库 / 接口 / 展示 / 操作」四处定义是否一致？
- [ ] 默认值是否经过用户确认？
- [ ] 危险操作是否用了统一弹窗？
- [ ] 新表格是否有 20 条分页？
- [ ] 文案里有没有内部实现词（置信度、规则编号、快照）？
- [ ] 空数据、加载中、失败、无权限四种状态是否都有界面？
- [ ] 是否写了对应的前后端测试？
- [ ] 是否截图自检过？
- [ ] 文档是否同步更新？

## 五、遗留事项（下一版处理）

1. 全局 AI 开关（首页两个入口决定是否启用 AI，顶部显示当前模式）；
2. 已有项目的产品画像编辑入口（目前只有新建时可填）；
3. 执行器后端落地：本地框架 → Jenkins → GitHub Actions（见 `docs/version-roadmap.md`）；
4. `cases.json` / `results.json` 格式规范与示例框架；
5. 执行结果回收、执行记录列表与报告联动；
6. 人工批次附件在新批次中的继承；
7. 自动化用例表与测试组中「同一底层用例两种执行方式」是否要提示更明确。
