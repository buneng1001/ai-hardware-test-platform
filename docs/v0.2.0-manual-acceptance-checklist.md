# v0.2.0 人工验收清单

本清单用于 v0.2.0 的人工验收。条目顺序按业务链路排列，不按 Issue 编号排列；每个阶段开头标注对应 Issue，便于回查实现记录。

## 1. 验收规则

1. 按顺序执行“操作”，与“预期结果”比对，在“结论”里填 `通过`、`不通过` 或 `跳过`。
2. `不通过` 必须在备注写明：页面现象、可复现的最短路径、相关接口 URL 与返回码、截图文件名。
3. `跳过` 必须写明原因（例如本机没有真实模型 Key）。
4. 判定标准：
   - 通过：A～K 阶段全部 `通过`。
   - 有条件通过：只有“真实模型”相关条目 `跳过`，其余全部 `通过`。
   - 不通过：任一阻断项 `不通过`（阻断项指会打断主流程闭环的条目）。
5. 本清单只验证 v0.2.0 已实现范围。第 12 节“已知限制”里的内容不算缺陷。

## 3. 环境准备

终端 1（后端，使用独立数据目录，避免污染现有 `data/`）：

```powershell
$env:APP_DATA_DIR = "data/acceptance"
$env:AI_DIAGNOSIS_MODE = "mock"
backend/.venv/Scripts/python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8020
```

终端 2（前端）：

```powershell
pnpm --dir frontend dev --host 127.0.0.1 --port 5173
```

**端口说明**：本机 8000 端口被另一个项目的后端占用，它返回的数据不属于本仓库。因此本次验收把后端放在 8020，
并把 `frontend/vite.config.ts` 的 `/api` 代理临时指向 `http://127.0.0.1:8020`。

**验收结束后必须还原**：`frontend/vite.config.ts` 里的代理要改回 `http://127.0.0.1:8000`，这处改动不能提交到分支。
