# 版本路线图

本文描述“智能硬件自动化方案管理平台”的预计演进路线。版本目标是规划内容，不能替代代码、测试或验收证据；只有已经产生可复查证据的能力，才能在面试材料中描述为已完成。

用户操作流程见 [用户视角使用流程与版本对应关系](user-flow-roadmap.md)，讨论形成的统一设计结论见 [平台设计结论](platform-design-conclusions.md)。

各版本的独立开发计划见：

- [v0.1.0 基础 POC 基线](plans/v0.1.0-baseline.md)
- [v0.2.0 项目治理、完整报告与准入规则](plans/v0.2.0-report-and-governance.md)
- [v0.3.0 AI 风险分析与用例推荐](plans/v0.3.0-ai-risk-and-cases.md)
- [v0.4.0 模拟设备与自动化执行](plans/v0.4.0-simulated-device.md)
- [v0.5.0 音频与多模态分析](plans/v0.5.0-multimodal.md)
- [v1.0.0 真实设备与企业级版本准入](plans/v1.0.0-enterprise-release.md)

## 总体演进

```text
v0.1.0 基础测试执行与诊断 POC
    ↓
v0.2.0 完整报告与准入规则
    ↓
v0.3.0 AI 风险分析与用例推荐
    ↓
v0.4.0 模拟设备控制与自动化执行
    ↓
v0.5.0 音频与多模态分析
    ↓
v1.0.0 真实设备与企业级版本准入
```

## 版本规划

### v0.1.0：基础测试执行与诊断 POC

当前版本的定位是跑通可复现的基础闭环，不接入真实硬件。

核心模块：

- 任务配置、运行记录、队列、取消、重跑和异常中断恢复。
- 合成或导入视频、IMU、设备状态和日志数据。
- 视频、IMU、存储、资源和日志的确定性检查。
- 固定偏移、线性漂移和跨模态事件对齐分析。
- 人工检查结果、基础 HTML 报告和 ZIP 证据包。
- Mock/硅基流动诊断适配、证据引用校验和安全降级。
- Pytest、Allure 和 GitHub Actions CI 骨架。

明确边界：没有测试前 AI 用例推荐、ADB/HTTP/Shell 设备控制、音频采集、Jenkins 和真实模型效果验证。

### v0.2.0：完整报告与准入规则（已完成）

目标是把当前基础报告升级为可用于版本评审的测试交付物。

核心模块：

- 报告模板和统一的测试结论页面。
- 视频、IMU、资源和日志的趋势图、统计摘要和异常时间线。
- 不同版本、设备配置和测试运行之间的结果对比。
- 通过、失败、阻塞、未执行等状态的统一汇总。
- 质量门禁规则、失败阻断策略和可解释的准入原因。
- 报告、证据包和 CI 产物之间的版本与哈希关联。

预期验收：同一版本可以生成结构一致的报告；失败检查能够触发明确的准入失败；报告能够支持历史版本对比。

**结项状态**：2026-11-13 的 UI 精修已合并 `main`（`0286708`），前端全量测试 172 项通过、3 项原有跳过；用户随后确认 v0.2.0 收工，版本标记为完成。完成范围为已约定的项目治理、数据驱动模拟测试与事实报告链路，企业级强制质量准入不据此宣称已验收。历史未复验条目保留原证据状态。剩余 AI 开关、产品画像和人工批次优化见 v0.3.0；真实执行器后端见 v0.4.0。

### v0.3.0：AI 调用控制与测试协同优化

目标是在保留 v0.2.0 现有测试管理和 C 方案 UI 的基础上，完善平台级 AI 运行控制、项目级产品画像、产品版本级 AI 补充说明、智能回归测试，以及人工测试与自动化测试的协同。

本版实际功能范围：

- **全局 AI 开关（01，P0）**：整个本机平台共享后端持久化状态；顶栏显示并切换 AI 状态；本期最多一项 AI 业务调用运行，不建设任务队列；每个 AI 调用入口提供就地取消/停止。开启必须满足配置已保存且当前配置指纹验证有效；存在活动调用时关闭需由用户确认停止当前调用或取消关闭。AI 配置维护与业务调用分离，关闭 AI 时仍可主动维护配置和测试连接。
- **项目级产品画像（02，P0）**：复用 v0.2.0 已有 ProductProfile 字段和表单，补齐已有项目的编辑入口；不新增版本级画像结构。
- **AI 需求分析（03，P0）**：本版真实保存产品版本级 AI 补充说明 `ai_context`，供同版本相关 AI 测试调用共享；需求分析、风险分析、用例推荐等未来链路仅保留可见入口，不实现实际分析。
- **智能回归测试建议（08，P1）**：针对现有测试组中的测试内容，结合同一项目（可跨产品版本、不跨项目）的历史测试信息生成回归建议；系统整理默认历史范围，用户可调整；独立于未来 AI 需求分析链路。
- **人工测试批次附件继承（09，P1）**：从指定历史人工批次创建新批次，继承用例范围并将附件复制为独立副本；执行状态重置为未执行，实际结果、备注和执行时间清空，保证新旧批次及历史证据相互独立。
- **人工与自动化用例关联展示（10，P1）**：保留原始人工用例与自动化用例为独立资产，支持一条原始用例关联多条自动化用例并双向追溯；原始用例表按自动化关联状态筛选，自动化用例表独立查看。

**仅做 UI 展示的未来 AI 业务链路（03–07）**：需求分析、风险分析、智能用例推荐、推荐审核与版本管理、AI 推荐结果与正式用例/自动化候选/测试组联动。本版只呈现必要入口，不实现真实分析、模型调用、需求分析结果保存、审核或发布流程。第 03 项的版本级 AI 补充说明 `ai_context` 是独立真实功能，不属于该未来链路。未来实际业务单独登记在 [后续开发计划项](plans/future-development-items.md)，版本待定。

**需求导入预留入口（11，P0）**：保留正常外观的入口，点击只提示“该功能开发中”，不执行文件选择、上传、读取或解析。

**AI 安全边界**：AI 只提供建议，不直接执行用例、不修改测试事实、确定性阈值或最终准入结论；AI 业务调用受全局开关统一控制。

### v0.3.0 补充：全局 AI 开关（01，P0）

- 「开启平台」且 AI 配置已保存、当前配置指纹对应的连接验证仍有效时启用 AI；否则阻止开启并引导用户先保存或重新验证。「暂不配置，进入平台」时关闭 AI。
- 整个本机平台共享一个后端持久化状态，不因切换项目、浏览器标签页或页面刷新而分裂。
- 顶栏常驻显示 AI 状态；启用时显示服务商和模型，并提供直接开启/关闭按钮。
- 全局关闭时仍允许用户主动编辑/保存 AI 配置、刷新模型列表和测试连接；禁止 AI 业务调用。业务调用运行期间允许编辑待测试参数、独立连接测试和目录刷新，不切换正式配置；保存正式配置须先完成当前调用或按既定弹窗停止并关闭 AI。正式配置指纹变更后重新验证、手动开启。
- 无活动 AI 调用时直接关闭；存在一项活动调用时，弹窗显示当前调用名称，只提供「停止当前的AI运行」与「取消这次关闭操作」。停止后取消当前调用并关闭 AI；取消后 AI 保持开启、调用继续，用户待调用结束后自行再次点击关闭，不自动等待关闭。
- 每个 AI 调用保留所属业务域的运行记录，运行状态与对应结果分开保存；每个调用入口提供就地取消/停止。其他 AI 入口在当前调用占用期间被点击时，只提示“当前有功能正在占用 AI，请稍后再试。”不排队、不自动重试。取消不得承诺第三方模型服务一定停止计算或计费。本期不创建 AI 任务队列、FIFO 或统一任务管理中心。
- 关闭 AI 不影响人工测试、规则转换、确定性检查和事实报告。

### v0.3.0 补充：项目级产品画像（02，P0）

- 复用 v0.2.0 新建项目时已有的 ProductProfile 字段和表单，不重新设计字段。
- 已有项目补齐「编辑产品画像」入口，并接通已有后端更新能力。
- 不做版本级画像覆盖；历史分析与报告快照不随画像编辑而改写。

### v0.3.0 的独立功能与验收

- 真实功能推进重点为 01、02、08、09、10；11 的预留入口单独验收。
- 03–07 只验收本期 UI 呈现及明确的视觉交互，不调用模型、不创建未来 AI 链路的业务数据。
- 第 08 项使用现有测试组内容及可用历史测试信息，不依赖需求文件导入或 03–07。
- 每项均需独立定义固定样例、人工操作步骤、明确预期结果和证据。AI 真实功能区分固定样例/Mock 功能证据与真实模型效果证据，不得混淆。
- 详细范围、验收边界和已确认裁决见 [v0.3.0 开发计划](plans/v0.3.0-ai-risk-and-cases.md)。

### v0.3.0 范围裁决：需求文件导入延后

本版不实现测试需求文件上传、读取、解析和格式适配。保留入口，点击时仅弹出「该功能开发中」，不打开文件选择器、不上传、不解析、不写入数据、不跳转、不模拟成功。需求文件导入安排在 v0.4.0 之后，具体版本待定，明确不纳入 v0.4.0。v0.2.0 已有正式测试用例表 CSV/XLSX 导入继续正常工作，不得误禁。


### v0.4.0：模拟设备控制与自动化执行

目标是让候选测试用例能够驱动一个可控的模拟设备执行。

核心模块：

- ADB 控制适配器：连接、启动、停止、状态查询和命令执行。
- HTTP 控制适配器：设备 API、健康检查和故障注入接口。
- Shell 控制适配器：受限命令白名单、超时、退出码和日志采集。
- 统一设备控制接口，隔离 ADB、HTTP 和 Shell 的具体实现。
- 用例步骤、前置条件、执行结果和设备日志的关联。
- 控制失败重试、超时、取消和设备状态恢复。

预期验收：同一测试用例可以通过统一接口切换不同模拟设备；每条控制命令都有结果、日志和超时证据。

### v0.4.0 补充：执行器与可执行用例（2026-11 验收后确定）

v0.2.0 的人工验收确认了"自动化不能只有模拟执行"，下一个版本按下面的方向落地。

**三种执行器（项目级配置，测试组从中选择）**

| 类型 | 平台做什么 | 结果怎么拿 |
| --- | --- | --- |
| 本地框架 | 把选中的用例导出成 `cases.json`，调用项目入口命令 | 读取框架写出的 `results.json` |
| Jenkins | 填地址 + 任务名 + 令牌，触发构建 | 轮询构建状态，完成后抓测试报告 |
| GitHub CI | 填 owner/repo + workflow + 令牌，`workflow_dispatch` | 轮询 run 状态，完成后下载 artifact |

统一约束：

- 执行器挂在**项目级**，多个测试组可以共用同一个执行器，触发时把测试组、用例集、数据包作为参数传入；
- 令牌不落明文，只存引用或加密字段；
- 执行前统一预检：用例已校验、数据包已分配、执行器连接正常。

**可执行用例的生成与审核**

```
选执行器 → 选用例 + 数据包 → 生成 cases.json
→ 结构校验（必须通过）→ 人工审核（可选跳过）→ 发布版本 → 执行 → 结果回写
```

- 结构校验：字段齐全、用例 id 有效、数据包路径存在；
- 人工审核：默认要求看一眼，允许勾选"我已确认，跳过逐条审核"；
- 发布后的 JSON 锁定版本，改用例必须重新生成。

**文件契约（第一版）**

```json
// cases.json
{
  "group": "智能硬件图像测试",
  "runner": "本地 pytest 框架",
  "format": "platform",
  "cases": [
    { "case_number": "AUTO-000001", "package": "DP-000001",
      "assert": { "metric": "frame_rate", "op": ">=", "value": 30 } }
  ]
}
```

```json
// results.json
{ "results": [
  { "case_number": "AUTO-000001", "status": "passed",
    "actual": { "frame_rate": 30.2 } }
] }
```

### v0.5.0：音频与多模态分析

目标是将音频纳入现有的视频、IMU、资源和日志分析链路。

核心模块：

- 音频采集、编码、采样率和时长检查。
- 音频断续、静音、削波和噪声等基础质量检查。
- 音频事件与视频帧、IMU 峰值、设备日志的时间对齐。
- 跨模态异常窗口和关联证据展示。
- 多模态证据包大小控制、脱敏和报告导出。
- 音频异常与视频/IMU 异常的组合场景。

预期验收：音频异常可以被独立检测，也可以在同一时间窗口内与其他模态进行确定性关联；不能仅凭时间相关性宣称根因。

### v0.4.0 之后的待规划事项（具体版本待定）

- 测试需求文件导入与解析：需求文档上传、文件格式兼容、原文追溯、内容提取及导入错误处理。待执行器阶段之后再规划与开发，具体版本待定，不纳入 v0.3.0 或 v0.4.0，也不默认挤占 v0.5.0 的音频与多模态范围。
- 原 v0.3.0 清单 03–07 的真实 AI 需求分析、风险分析、用例推荐、审核与发布联动：仅保留本版 UI，实际业务能力暂缓，未来版本待定。
- 以上暂缓项目的边界与重新启动要求见 [后续开发计划项](plans/future-development-items.md)，后续须单独 To Spec、拆票和人工验收。

### v1.0.0：真实设备与企业级版本准入

目标是从本地演示 POC 发展为可接入真实硬件和企业 CI 的测试平台。

核心模块：

- 真实设备适配器、设备发现、连接管理和能力探测。
- 真实采集链路、设备资源指标和现场日志采集。
- 设备固件/软件版本管理和兼容性矩阵。
- 版本回归选择、历史结果追踪和失败趋势分析。
- GitHub Actions 正式质量门禁和 Jenkins 对照流水线。
- 测试结果、报告和证据包的正式版本准入。
- 权限、凭据隔离、审计记录和企业部署配置。

正式准入原则：模型只能提供辅助分析；设备控制、确定性检查、质量门禁和最终准入必须保留可复查的工程证据。

## 版本边界

以下内容不应在 v0.1.0 阶段对外宣称已经完成：

- AI 测试前风险分析和测试用例推荐。
- ADB、HTTP、Shell 或其他真实/模拟设备控制。
- 音频、蓝牙和真实 MCAP 数据链路。
- 完整报告模板、版本对比和企业级质量门禁。
- Jenkins 流水线和真实模型线上效果。

每个版本完成后，应同步更新 [首版验收清单](v1-acceptance-checklist.md)、[课程映射](course-coverage.md) 和 [面试案例](interview-case.md)，并为已完成项补充测试或产物证据。
