# 版本路线图

本文描述“AI 智能硬件测试执行与诊断平台”的预计演进路线。版本目标是规划内容，不能替代代码、测试或验收证据；只有已经产生可复查证据的能力，才能在面试材料中描述为已完成。

用户操作流程见 [用户视角使用流程与版本对应关系](user-flow-roadmap.md)，讨论形成的统一设计结论见 [平台设计结论](platform-design-conclusions.md)。

各版本的独立开发计划见：

- [v0.1.0 基础 POC 基线](plans/v0.1.0-baseline.md)
- [v0.2.0 项目治理、完整报告与准入规则](plans/v0.2.0-report-and-governance.md)
- [v0.3.0 AI 风险分析与用例推荐](plans/v0.3.0-ai-risk-and-cases.md)
- [v0.4.0 模拟设备与自动化执行](plans/v0.4.0-simulated-device.md)

## 版本规划

### v0.1.0：基础测试执行与诊断 POC

当前版本的定位是跑通可复现的基础闭环，不接入真实硬件。

核心模块：

- 任务配置、运行记录、队列、取消、重跑和异常中断恢复。
- 合成或导入视频、IMU、设备状态和日志数据。
- 视频、IMU、存储、资源和日志的确定性检查。
- 固定偏移、线性漂移和跨模态事件对齐分析。
- 人工检查结果、基础 HTML 报告和 ZIP 证据包。
- Mock/硅基流动诊断适配、证据引用校验和安全降级。
- Pytest、Allure 和 GitHub Actions CI 骨架。

明确边界：没有测试前 AI 用例推荐、ADB/HTTP/Shell 设备控制、音频采集、Jenkins 和真实模型效果验证。

### v0.2.0：完整报告与准入规则

目标是把当前基础报告升级为可用于版本评审的测试交付物。

核心模块：

- 报告模板和统一的测试结论页面。
- 视频、IMU、资源和日志的趋势图、统计摘要和异常时间线。
- 不同版本、设备配置和测试运行之间的结果对比。
- 通过、失败、阻塞、未执行等状态的统一汇总。
- 质量门禁规则、失败阻断策略和可解释的准入原因。
- 报告、证据包和 CI 产物之间的版本与哈希关联。

预期验收：同一版本可以生成结构一致的报告；失败检查能够触发明确的准入失败；报告能够支持历史版本对比。

### v0.3.0：AI 风险分析与测试用例推荐

目标是让 AI 参与测试前的分析，而不仅仅是运行后的诊断。

核心模块：

- 测试需求、设备配置和版本变更的结构化输入。
- AI 识别高风险功能、数据链路和潜在故障模式。
- 根据风险、历史失败和覆盖情况推荐测试类型与测试场景。
- 输出推荐理由、优先级、依赖条件和缺失信息。
- 将推荐结果转换为平台可执行的候选任务配置。
- 推荐结果的 Schema 校验、人工确认和版本化保存。

安全边界：AI 只提出建议，不直接修改测试事实、阈值或最终准入结论；确定性规则仍负责正式检查。

### v0.4.0：模拟设备控制与自动化执行

目标是让候选测试用例能够驱动一个可控的模拟设备执行。

核心模块：

- ADB 控制适配器：连接、启动、停止、状态查询和命令执行。
- HTTP 控制适配器：设备 API、健康检查和故障注入接口。
- Shell 控制适配器：受限命令白名单、超时、退出码和日志采集。
- 统一设备控制接口，隔离 ADB、HTTP 和 Shell 的具体实现。
- 用例步骤、前置条件、执行结果和设备日志的关联。
- 控制失败重试、超时、取消和设备状态恢复。

预期验收：同一测试用例可以通过统一接口切换不同模拟设备；每条控制命令都有结果、日志和超时证据。

### v0.5.0：音频与多模态分析

目标是将音频纳入现有的视频、IMU、资源和日志分析链路。

核心模块：

- 音频采集、编码、采样率和时长检查。
- 音频断续、静音、削波和噪声等基础质量检查。
- 音频事件与视频帧、IMU 峰值、设备日志的时间对齐。
- 跨模态异常窗口和关联证据展示。
- 多模态证据包大小控制、脱敏和报告导出。
- 音频异常与视频/IMU 异常的组合场景。

预期验收：音频异常可以被独立检测，也可以在同一时间窗口内与其他模态进行确定性关联；不能仅凭时间相关性宣称根因。

### v1.0.0：真实设备与企业级版本准入

目标是从本地演示 POC 发展为可接入真实硬件和企业 CI 的测试平台。

核心模块：

- 真实设备适配器、设备发现、连接管理和能力探测。
- 真实采集链路、设备资源指标和现场日志采集。
- 设备固件/软件版本管理和兼容性矩阵。
- 版本回归选择、历史结果追踪和失败趋势分析。
- GitHub Actions 正式质量门禁和 Jenkins 对照流水线。
- 测试结果、报告和证据包的正式版本准入。
- 权限、凭据隔离、审计记录和企业部署配置。

正式准入原则：模型只能提供辅助分析；设备控制、确定性检查、质量门禁和最终准入必须保留可复查的工程证据。

## 版本边界

以下内容不应在 v0.1.0 阶段对外宣称已经完成：

- AI 测试前风险分析和测试用例推荐。
- ADB、HTTP、Shell 或其他真实/模拟设备控制。
- 音频、蓝牙和真实 MCAP 数据链路。
- 完整报告模板、版本对比和企业级质量门禁。
- Jenkins 流水线和真实模型线上效果。

每个版本完成后，应同步更新 [首版验收清单](v1-acceptance-checklist.md)、[课程映射](course-coverage.md) 和 [面试案例](interview-case.md)，并为已完成项补充测试或产物证据。
